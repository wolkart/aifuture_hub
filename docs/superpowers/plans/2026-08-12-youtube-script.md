# youtube-script Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Скилл `youtube-script`, который превращает тему в буллет-сценарий обучающего YouTube-ролика: структура целиком, раскадровка по дублям, добытая по первоисточнику фактура, контроль регистра объяснений.

**Architecture:** `SKILL.md` — только оркестрация (вход → тип ролика → добыча матчасти → каркас → раскадровка → проверки). Вся вариативность в `references/`: формат файла сценария, каркас с десятью пунктами, эталон разжёвывания, замеры. Ядро инструкции генерируется через `meta-prompt` (правило [CLAUDE.md](../../../CLAUDE.md)), упаковка — через `skill-creator`.

**Tech Stack:** Markdown. Никаких скриптов — скилл текстовый. Внешние источники: `context7` MCP и веб-поиск для матчасти; `youtube-analytics` как поставщик замеров.

## Global Constraints

Требования ниже действуют на **каждую** задачу.

- **Язык — русский.** Все файлы скилла, включая `description`.
- **Никаких числовых порогов как норм.** Запрещены формулировки вида «подводка до 60 секунд», «оптимальная длина 8–12 минут», «не более N дублей». Числа существуют только как датированная справка с `n` и конфаундами в `references/measurements.md`. Основание — спека §5.
- **У каждого замера названы `n`, дата и конфаунд.** Правило `evidence-law` (`../../../skills/brand-voice/references/evidence-law.md`).
- **Границы не размывать:** мету (тайтл/описание/теги/превью) пишет `youtube-meta`; Shorts — `reels-script`; хуки из `hook-base` не берутся (та база снята с ленты, YouTube поисковый).
- **Публичный репозиторий:** ни личных хендлов, ни выручки, ни имён каналов конкурентов с их метриками. В примерах — плейсхолдеры.
- **Проверенное ядро через `meta-prompt` не гоняется.** Десять пунктов структуры и приёмы эталона разжёвывания входят как готовый материал; `meta-prompt` генерирует обвязку вокруг них. Основание — принцип, зафиксированный при работе над `strategist`.

### Task 2: `references/script-format.md`

Формат самого файла сценария. Отдельно от каркаса: каркас отвечает «что говорить», формат — «как это записано на бумаге».

**Files:**
- Create: `skills/youtube-script/references/script-format.md`

**Interfaces:**
- Produces: имена меток `▸`, `»`, `⌘`, `❓`, `📊`; заголовок дубля `🎬 Дубль N`. Task 3 и Task 6 ссылаются на эти метки.

- [ ] **Step 1: Написать файл**

Содержание — из спеки §4, плюс раскадровка по дублям из проекта курса. Обязательные блоки:

1. **Дубли.** `- [ ] ### 🎬 Дубль N — <короткое имя> (~N сек)`. Один дубль = одна мысль или одно действие на экране. Сбился — перезаписывается один дубль. Чекбокс для трекинга записи.
2. **Две дорожки внутри дубля:** `**Экран:**` и речь. Визуал и звук разведены намеренно — приём экономит время на записи и монтаже.
3. **Таблица трёх типов буллета** — скопировать из спеки §4 без изменений.
4. **Порог «что прописывать»:** пишем то, что нельзя восстановить, глядя на экран. Где крестик окна — не пишем. Флаг команды и зачем он — пишем.
5. **Метка `❓ проверить до записи`** — незакрытая дыра в фактуре.
6. **Метка `📊 Экран: открываю схему`** — если в дубле показывается схема, указывается явно, иначе на записи непонятно, когда её выводить.
7. **Правило самодостаточности:** все промты, команды и реплики внутри файла. Автор на записи никуда не переключается.
8. **Пример дубля целиком** — на обезличенной теме (установка условного инструмента), со всеми тремя типами буллета.

- [ ] **Step 2: Проверить, что нет числовых норм**

Run: `grep -nE '[0-9]+\s*(сек|секунд|минут|мин)\b' skills/youtube-script/references/script-format.md`
Ожидание: совпадения только внутри примера дубля (`~40 сек` как иллюстрация хронометража конкретного дубля), ни одного в виде правила. Если правило — переписать.

- [ ] **Step 3: Коммит**

```bash
git add skills/youtube-script/references/script-format.md
git commit -m "youtube-script: формат буллет-сценария (дубли, две дорожки, три типа буллета)"
```

### Task 3: `references/backbone.md`

Каркас ролика. Самый содержательный файл скилла.

**Files:**
- Create: `skills/youtube-script/references/backbone.md`

**Interfaces:**
- Consumes: метки из Task 2
- Produces: названия десяти пунктов и формулировку двух вопросов — Task 6 ссылается на них из `SKILL.md`

- [ ] **Step 1: Написать раздел «Десять пунктов»**

Перечислить дословно: привлечение внимания → заявление темы → боль → усиление боли → история → надежда → раскрытие темы → мотивация действовать → предложение → итоги.

Сразу за списком — рамка применения, дословно по спеке §5:

> Пункты — чек-лист функций, а не десять абзацев. По каждому задаются два вопроса:
> 1. Делает ли пункт здесь работу?
> 2. Сколько эта работа стоит в этой теме — фраза, кадр или две минуты?
>
> Длина подводки — следствие этих решений, а не входной параметр.

- [ ] **Step 2: Написать раздел «Решение видно в файле»**

Пункт либо присутствует в сценарии, либо в конце файла стоит строка вида «боль снята — зритель приходит с готовым намерением, давить не на что». Молча исчезнуть пункт не может: автор должен видеть, что его взвесили, и иметь возможность поспорить.

- [ ] **Step 3: Написать раздел «Тест перехода»**

После каждого блока: **есть ли у зрителя прямо сейчас причина закрыть ролик?** Есть — блок не готов. Отдельный проход по готовому сценарию, обязателен всегда, независимо от типа ролика.

- [ ] **Step 4: Написать раздел «Типы роликов»**

Три типа — разбор инструмента / ролик-мнение / курс. Тип задаёт **вес и бюджет** пунктов, а не их набор. Для каждого — одна строка про то, откуда приходит зритель и что из этого следует.

- [ ] **Step 5: Написать раздел «Остальное по каркасу»**

Из спеки §5: доказательство права говорить правдой без смягчения (различие с инфобизнесом проходит по правдивости, а не по громкости); кривая удержания как горки (пик → разгрузка → подъём); предложение только в конце (в первые секунды у зрителя нет причины его выполнять); концовка короче вступления; резерв пользы вместо воды — частые ошибки и «чего не делать».

- [ ] **Step 6: Написать раздел «Направление типичного провала»**

Подводка раздувается сама, а не ужимается. Финальная проверка: «каждая минута до раскрытия темы отработала или просто набралась?». Это единственное, что зашивается вместо нормы.

- [ ] **Step 7: Проверить отсутствие порогов**

Run: `grep -nE 'до [0-9]+ (сек|минут)|не более [0-9]|оптимальн' skills/youtube-script/references/backbone.md`
Ожидание: пусто. Любое совпадение — нарушение Global Constraints, переписать в критерий.

- [ ] **Step 8: Коммит**

```bash
git add skills/youtube-script/references/backbone.md
git commit -m "youtube-script: каркас — десять пунктов как чек-лист функций"
```

### Task 4: `references/explaining.md`

Эталон разжёвывания. Чек-лист по дублю, не текст для чтения вслух.

**Files:**
- Create: `skills/youtube-script/references/explaining.md`

- [ ] **Step 1: Написать три приёма**

Дословно по смыслу источника (эталонная инструкция из другого продукта автора):

1. **Описывать то, что человек видит на экране,** а не чем оно является. «Откроется окно с мигающим курсором» вместо «запустится эмулятор терминала». Зритель сверяет глазами, а не воображением.
2. **Обезвредить испуг заранее** — до того, как он случился. «При вводе пароля на экране ничего не появляется — это не зависание, так сделано специально».
3. **Вести за состоянием, а не по кнопкам:** «куда надо попасть» + «как убедиться, что получилось». Интерфейсы меняются, состояние — нет.

Формула: не строй игрушечную модель реальности — опиши саму реальность простыми словами, стоя рядом с человеком.

- [ ] **Step 2: Написать раздел «Как это живёт в буллетах»**

Приёмы — **напоминания, а не реплики**. Буллет `▸ сказать: при вводе пароля на экране ничего не появится` — это метка «здесь зритель испугается, обезвредь заранее», а не текст для чтения. Слова автор подберёт сам.

- [ ] **Step 3: Написать запреты регистра**

Без сюсюканья («вот ящичек, положи сюда»). Без подбадривания («это не магия», «сейчас успокою», «чтобы не было паники») — не считать зрителя идиотом. Без жаргона напоказ. Взрослый язык: назвать вещь и объяснить.

- [ ] **Step 4: Написать чек-лист по дублю**

Пять галочек, применяются к каждому дублю, где что-то объясняется:
- [ ] описано то, что видно на экране?
- [ ] испуг обезврежен до того, как случился?
- [ ] сказано, как убедиться, что получилось?
- [ ] нет подбадривания и сюсюканья?
- [ ] термин введён через «зачем», а не учебниковым определением?

- [ ] **Step 5: Коммит**

```bash
git add skills/youtube-script/references/explaining.md
git commit -m "youtube-script: эталон разжёвывания как чек-лист по дублю"
```

- [ ] **Step 1: Перенести замеры из спеки §10**

Обезличенно («канал А», «канал Б», «русскоязычный канал ниши»). Дата прогона — 2026-08-12. Обязательно перенести:

Три метки по `evidence-law`: **замерено** (биты вступлений, доли жанров, тайминг референса), **выведено** (объяснение «зритель с готовым намерением терпит подводку хуже» — логика поверх замера, отдельно не проверялась), **не проверено** (перенос на русскоязычную аудиторию целиком — замерен один канал).

- [ ] **Step 4: Написать раздел «Как обновить»**

Прогон `youtube-analytics` в режиме `enrich` по топам нужного канала; числа заменяются целиком вместе с датой и `n`. Руками цифры не подкручиваются.

### Task 6: `SKILL.md` через `skill-creator`

**Files:**
- Create: `skills/youtube-script/SKILL.md`
- Read: `<scratchpad>/youtube-script-core.md` (Task 1), все четыре `references/`

**Interfaces:**
- Consumes: метки из Task 2, названия пунктов из Task 3, чек-лист из Task 4, статус замеров из Task 5
- Produces: `description` с триггерами — по нему скилл срабатывает

- [ ] **Step 1: Вызвать `skill-creator` для упаковки**

Передать: черновик ядра из Task 1, спеку, готовые `references/`. Требование — `SKILL.md` содержит **только оркестрацию**, вариативность остаётся в `references/` и не дублируется.

- [ ] **Step 2: Написать `description` с триггерами**

Формат — как у соседей (`youtube-meta`, `reels-script`): что делает, на чём стоит, когда вызывать дословными фразами пользователя, и чего НЕ делает.

Триггеры включить: «напиши сценарий для ролика», «сценарий для ютуба», «раскадруй ролик», «сделай буллет-сценарий», «разбери со мной инструмент и напиши сценарий», «сценарий обучающего видео», «подготовь ролик к записи».

Границы в `description`: НЕ пишет тайтл и описание (`youtube-meta`), НЕ про Shorts (`reels-script`), НЕ анализирует каналы (`youtube-analytics`).

- [ ] **Step 3: Написать порядок работы**

Шаги в `SKILL.md`:
0. **Принять вход.** Тема и предмет обязательны; голосовая расшифровка автора — **штатный вход наравне с текстом**, а не исключение (текст, рождённый в речи, ложится на камеру органичнее написанного). Опционально: черновик, референсный ролик, целевой хронометраж.
1. **Разобраться в предмете.** Если инструмент незнаком — идти в первоисточник (`context7`, официальная дока, при нужде веб) **до** сценария: что он делает, что стоит показать зрителю, где грабли. Помечать, что подтверждено докой, а что чужое утверждение.
2. **Определить тип ролика** — `references/backbone.md`, раздел «Типы роликов». Не угадывать молча: если из входа тип не читается, спросить одним вопросом.
3. **Пройти по десяти пунктам** с двумя вопросами на каждый.
4. **Разложить на дубли** по `references/script-format.md`.
5. **Прогнать тест перехода.**
6. **Прогнать чек-лист разжёвывания** по каждому дублю, где что-то объясняется.
7. **Проверить метки `❓`** — есть незакрытые, сценарий не готов, сказать об этом прямо.

- [ ] **Step 4: Написать раздел «Дисциплина ответа»**

По образцу `youtube-analytics`: пользователю нужен результат, а не отчёт о ходе мыслей. Ресёрч и проверки делать молча. Видимый ответ — путь к файлу, тип ролика, список снятых пунктов с причинами, список незакрытых `❓`.

- [ ] **Step 5: Проверить размер и отсутствие дублирования**

Run: `wc -l skills/youtube-script/SKILL.md skills/youtube-script/references/*.md`
Ожидание: `SKILL.md` заметно короче суммы `references/`. Если он длиннее любого reference — в него утекла вариативность, вынести.

- [ ] **Step 6: Проверить, что все ссылки живые**

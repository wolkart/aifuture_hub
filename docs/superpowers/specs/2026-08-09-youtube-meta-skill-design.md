# Скилл `youtube-meta` + режим превью в `youtube-analytics` — дизайн

**Дата:** 2026-08-09
**Статус:** утверждён (брейншторм)
**Маршрут дальше:** writing-plans → реализация в два этапа → боевой прогон на своём канале

## Проблема

Под длинное горизонтальное YouTube-видео нет генератора меты: тайтл, описание, теги, главы. Всплывало дважды, оба раза поднимали веб-ресёрчем руками — то есть общими канонами из статей, а не своими данными.

Теперь данные есть: `youtube-analytics` собрал пять каналов (947 роликов), и часть расхожих канонов на них **не подтвердилась**. Писать скилл по чужим статьям, имея свои замеры, было бы прямой ошибкой.

Отдельная проблема — перенос референса. Автор уже делал это руками: взял ролик Ника Сараева `How to Use Claude Code for FREE (2026)` и перестроил под себя. Получилось (20× подписной базы), но три элемента меты он не перенёс, потому что переносил на глаз.

## Установка автора (рамка всей работы)

**Не переносить правила из скиллов для ленты в YouTube механически.** Только если оправдано на 100%; при сомнении — писать отдельно под YouTube. Лента и поиск — разные площадки и разная аудитория.

Конкретный случай, где правила расходятся: в `copy-law` и `reels-script` записано, что имя инструмента в хуке проигрывает выгоде в 10–30 раз (замер 124 постов). На YouTube имя инструмента в тайтле **в плюс** на трёх каналах из четырёх. Противоречия нет: лента показывает непрошеное, YouTube поисковый — имя и есть запрос. Но это надо держать разведённым явно, иначе скилл унаследует правило не с той площадки.

Исключение, названное автором: Reels и Shorts он публикует одни и те же, меняя только CTA. То есть общность допустима там, где формат физически один.

## Замеры, на которых стоит скилл

Снято `youtube-analytics` 2026-08-09. Читается как «медиана кратности С признаком / БЕЗ признака (n роликов с признаком)». Кратность = просмотры / медиана своего типа на своём канале.

| Признак тайтла | Сараев (en, 492k) | Нейт Хёрк (en, 924k) | ИИшенка (ru, 24.6k) | Vibecoder (ru, 14.4k) | Вердикт |
|---|---|---|---|---|---|
| **бесплатно / FREE** | 3.61 / 0.98 (7) | 1.32 / 1.0 (4) | 1.12 / 1.0 (10) | 2.97 / 0.96 (10) | **4 из 4 — универсально** |
| **курс / гайд / «полный»** | 5.38 / 0.94 (19) | 1.31 / 0.99 (16) | 4.04 / 1.0 (2) | 3.59 / 0.97 (2) | **4 из 4**, на русских n<5 |
| **имя инструмента** | 1.31 / 0.92 (89) | 1.24 / 0.74 (188) | 0.96 / 1.01 (101) | 1.32 / 0.62 (24) | 3 из 4 |
| **цифра** | 1.14 / 0.87 (190) | 1.05 / 0.87 (185) | 0.79 / 1.01 (65) | 1.24 / 0.89 (25) | 3 из 4 |
| CAPS-слово | 1.03 / 0.97 (47) | 1.0 / 1.0 (34) | 1.04 / 0.99 (66) | **0.98 / 1.38** (42) | **стоп-лист** |
| скобки | 1.3 / 0.86 (115) | 0.96 / 1.02 (80) | 0.75 / 1.01 (26) | 1.29 / 0.81 (14) | **стоп-лист** (разнобой) |
| отрицание лидера | 0.97 / 1.0 (11) | **0.61 / 1.01** (11) | — (0) | 1.99 / 0.98 (3) | **стоп-лист** (разнобой) |
| тег года `(2026)` | **7.96 / 0.96** (8) | не ставит | не ставит | не ставит | приём одного канала |

**Текст на превью** (Vibecoder School, 47 из 47 распознаны Apple Vision):

| Признак на превью | С / без | n |
|---|---|---|
| **БЕСПЛАТНО** | **3.75 / 0.96** | 6 |
| запрет («перестань», «хватит») | 1.59 / 0.98 | 3 |
| имя платного инструмента | 1.31 / 0.96 | 16 |
| цифра или сумма | 1.19 / 0.72 | 31 |
| текст ≤4 слов | **0.89 / 1.27** | 14 |

Два вывода. На превью работает **та же ось, что в тайтле** — цена, имя инструмента, конкретика. И расхожий совет «2–4 слова на превью» здесь **опровергнут**: короткие дают 0.89 против 1.27. Ровно этот совет попал бы в скилл, если бы писали по общим канонам.

### Что из этого НЕ является выводом

- **Описание не оценено на причинность и не может быть.** У Сараева и Нейта первые 125 символов — константа-оффер, одинаковая у топа и у середины; величина, которая не меняется, не может объяснять разницу. У Сараева оффер менялся между периодами, но вместе с нишей и временем — фактор неотделим. Поэтому описание в скилле трактуется как **воронка и SEO-подложка, а не рычаг охвата**. Рычаг — тайтл и превью.
- **Тег года** остаётся приёмом одного канала: три остальных не ставят его вовсе, поэтому «не работает» про них сказать нельзя — данных просто нет.
- **Формат курса на русских каналах** имеет n=2, ниже порога надёжности. Подтверждён на англоязычных (n=19 и n=16), на русских — сигнал того же направления.

## Решения по развилкам (утверждено)

| Развилка | Решение |
|---|---|
| Охват скилла | **Только мета:** тайтл, описание, теги, главы. Вступление (первые 60 сек) — отдельный скилл позже, когда наберётся больше разобранных вступлений через `enrich` |
| Анализ превью | **Режим в `youtube-analytics`, не в `youtube-meta`.** Меряет тот, кто меряет; применяет тот, кто пишет |
| Язык | Замеры сняты на двух англоязычных и двух русскоязычных каналах. Универсальные признаки подтверждены на обоих языках |
| Первые 125 символов описания | **Хук по содержанию с ключевиками**, оффер вторым абзацем. На канале в сотню подписчиков сначала нужно, чтобы находили |
| Два тайтла | **Первый — максимум подтверждённых сигналов. Второй — другая дверь**, а не переформулировка: иначе тест не различает гипотезы |
| Перенос референса | **Третий режим**, с проверкой годности на входе |
| Превью-подсказка в мете | Входит, но только как **проверенные текстовые признаки**, без советов по дизайну и композиции |

## Этап 1: режим `thumbs` в `youtube-analytics`

Новый режим поверх собранного `.channel.json`.

1. Качает превью по `thumbnail_url` (параллельно, 8 потоков; 47 штук ≈ 2 секунды).
2. Снимает текст `scripts/ocr-cards.sh` — Apple Vision, локально, бесплатно, ~0.07 с на превью.
3. Считает срез: наличие слова «бесплатно», имени платного инструмента, цифры/суммы, запрета; длина текста в словах — против медианной кратности, с тем же порогом надёжности 5.
4. Дописывает распознанный текст в карточку ролика (секция `## Текст на превью`) и добавляет раздел в `Разбор — тайтлы и паттерны.md`.

**OCR-скрипт копируется** из `instagram-analytics/scripts/` в `youtube-analytics/scripts/`, а не вызывается по соседству. Причина: скиллы подключаются симлинками поштучно и забираются из публичного хаба по одному — межскилловая ссылка на файл сломается у любого, кто возьмёт только YouTube-ветку. Два файла дублирования дешевле хрупкой связи.

**Ограничение, которое режим обязан печатать:** только macOS (Apple Vision). Нет `swiftc` — режим честно отказывается, остальные режимы работают.

**Превью не хранятся:** качаются во временную папку, после OCR удаляются. В карточку идёт `thumbnail_url` и распознанный текст, не файл. Правило то же, что «видео не храним».

## Этап 2: скилл `youtube-meta`

### Три режима

**`СОБРАТЬ`** (дефолт) — вход: тема ролика и что в нём реально показано. Выход:

1. **Два тайтла.** Первый собран из подтверждённых сигналов под тему; второй — другой угол входа. К каждому: из каких сигналов собран и какой первым в тест.
2. **Описание** по шаблону автора: хук с ключевиками (≈125 символов) → оффер-ссылка → блок «если видишь меня впервые» → ссылки на свои длинные ролики → `Summary` с ключевиками → инструменты → `Chapters`.
3. **Теги** — ориентир 20–40, от общего к частному. Число взято из медианы Сараева (37 тегов на ролик); у Нейта тегов почти нет при вдвое большей аудитории, поэтому скилл прямо говорит: **это гигиена, а не рычаг роста**.
4. **Каркас глав** с обязательной первой меткой `00:00`.
5. **Текст на превью** — 2–3 варианта из проверенных признаков.

**`ПРОВЕРИТЬ`** — вход: URL опубликованного ролика или черновик меты. Прогоняет по сигналам и выдаёт список конкретных поломок с приоритетом. Окупается сразу: у автора семь роликов без тегов и с главами, начинающимися не с `00:00`.

**`ПЕРЕНОС`** — вход: URL референса (чужого ролика) + своя тема. Разбирает механику референса и собирает свою версию.

Данные о референсе скилл **не добывает сам, а делегирует** `youtube-analytics` (его `enrich` уже умеет вступление и главы, `scout` — мету). Прямой вызов чужих скриптов запрещён по той же причине, по которой OCR копируется, а не шарится: скиллы подключаются поштучно и ломаются в отрыве. Референс уже есть в собранной базе — берём оттуда, нет — сначала прогон аналитики.

**Проверка годности референса — до сборки**, по образцу `carousel-script`. Не переносится: ценность на личном доказательстве автора (скриншоты его заработка, его прогоны) и витрина чужих продуктов. Переносится структура, не оболочка. Не проходит — скилл говорит прямо, а не выдаёт пустой каркас.

### Порядок теста тайтлов

Первым публикуется вариант с максимумом подтверждённых сигналов. Замер — **первые 48 часов, по кратности к медиане своего типа** (CTR публичный API не отдаёт, поэтому меряем просмотрами). Не вышел на свою планку — ставится второй вариант.

Скилл обязан сказать: **два похожих тайтла — бессмысленный тест.** Второй вариант меняет угол входа, а не формулировку.

### Голос — посекционно

По таблице двух слоёв из `brand-voice/SKILL.md`, без переноса правил ленты:

| Секция | Закон текста | Голос автора |
|---|---|---|
| Тайтл | да | нет |
| Первые ~125 символов описания | да | нет |
| Блок «если видишь меня впервые» | да | **да, целиком** |
| `Summary` | да | нет |
| Ссылки, инструменты, `Chapters`, теги | нет | нет |

**Оговорка, обязательная к соблюдению:** правило `copy-law` про имя инструмента на YouTube **инвертировано** — имя в тайтле работает, потому что это поисковый запрос. Скилл держит эту оговорку у себя и не тянет запрет из ленты.

### Предохранители

- **Мета не обещает того, чего в ролике нет.** Мисматч режет удержание. Не ясно из входа, что показано, — скилл спрашивает, а не додумывает.
- **Мета не сочиняется из транскрипта.** Транскрипт — источник фактов, не источник формулировок.
- **Числа замеров датированы.** Скилл не пересчитывает их сам — это работа `youtube-analytics`. Устарели — сказать и предложить прогон.
- **Стоп-лист не обходится молча.** Просят CAPS или скобки — ставит, но с пометкой «приём одного канала, у Vibecoder вредит».

### Структура

```
skills/youtube-meta/

  README.md
  references/
    title-signals.md                ← таблица замеров + стоп-лист + как собирать тайтл
    description-template.md         ← шаблон описания, что константа, что меняется
    tags-chapters-thumbnail.md      ← теги, главы с 00:00, текст на превью
```

Скриптов нет: скилл ничего не считает и никуда не ходит — вся арифметика осталась в `youtube-analytics`.

## Что осознанно не входит

- **Советы по дизайну и композиции превью** (лицо, эмоция, контраст). CTR недоступен, композицию не мерили — это был бы пересказ чужих статей. Только текстовые признаки, которые померили.
- **Вступление ролика** — отдельный скилл, после накопления разборов через `enrich`.
- **Shorts-мета** — у Shorts другая механика (лента, а не поиск), и там как раз работают правила `reels-script`. Отдельная запись в `BACKLOG.md` остаётся открытой.
- **Автопостинг и правка меты через API** — `videos.update` требует OAuth и права записи на канал. Скилл выдаёт текст, публикует человек.
- **Подбор ключевых слов по объёму запросов** — таких данных в API нет, выдумывать нельзя.

## Критерии готовности

1. Режим `thumbs` отрабатывает на канале Vibecoder и воспроизводит замеры из этой спеки.
2. Режим `thumbs` честно отказывается без `swiftc`, не ломая остальные режимы.
3. `youtube-meta` в режиме `СОБРАТЬ` выдаёт два тайтла с указанием, какой первым и почему.
4. Режим `ПРОВЕРИТЬ` на реальном ролике автора находит обе известные поломки: отсутствие тегов и главы не с `00:00`.
5. Режим `ПЕРЕНОС` на ролике Сараева `How to Use Claude Code for FREE (2026)` признаёт референс годным (ценность в способе, а не в личном доказательстве) и собирает версию под тему автора. На контрольном примере — ролике, где ценность держится на скриншотах чужого заработка, — отказывается и объясняет причину.
6. Скилл ни разу не тянет запрет на имя инструмента из `copy-law`.
7. Добавлен в `skills/README.md`, подключён через `install-skills.sh`.

# `/reel` и `motion-assets`: рилс без монтажки и библиотека моушн-графики

Дата: 2026-10-13. Статус: проект. Прототип собран руками в контент-сессии 2026-10-12/13: четыре версии одного рилса и проба моушн-графики. Все решения ниже проверены на нём, цифры оттуда же.

## Проблема

Блогеры показывают рилсы, смонтированные агентом «одной командой»: тишина вырезана, субтитры по слову, графика под слова, наезды, музыка. У нас есть `rough-cut` (черновая резка), а всего остального нет. Прототип показал, что результат уровня «можно выкладывать» достижим. Но он держится на десятке ручных решений, которые сейчас живут только в одной сессии и в разовых скриптах:

1. **Резка ≠ монтаж.** `rough-cut` отдаёт cut-list и mp4, а субтитры, вставки, наезды и музыку собирать нечем.
2. **Готовые стили HyperFrames не годятся для русского.** Все шрифты каталога `embedded-captions` только латиница, DNA-стили заточены под 16:9. Субтитры и карточки пришлось писать своим HTML.
3. **Б-роллы по темам дают слабый монтаж.** Первая версия ставила один б-ролл на фразу на 2–3 с, и автор оценил вставки как «не самые лучшие». Его собственный рилс сделан по ключевым словам, вставками по 0,8–1,5 с, и это сильнее.
4. **Нет библиотеки графики.** Каждая карточка рисуется заново под ролик. Нет ни шаблонов, ни описи своих б-роллов, ни переиспользования.

## Что доказал прототип

| Этап | Что сработало | Время |
|---|---|---|
| Резка | `rough-cut` + границы речи по петличке + стадия «Взгляд» (уже в скилле с 2026-10-13) | секунды; взгляд ~40 с на 3 мин |
| Расшифровка | Whisper по смонтированному файлу + словарь замен + `snap_words.py` (слова после пауз шли на 0,3–0,4 с раньше голоса, стало ±0,1 с) | ~1 мин |
| Субтитры и карточки | свой HTML на HyperFrames: страницы по 2 строки, подсветка текущего слова, карточки на ключевых словах | рендер ~1,5 мин |
| Наезды | генератор плана: масштаб на склейке меняется ≥ 0,1, «вжух» +0,12 за 0,16 с на ударном слове, центр — лицо | рендер ~50 с |
| Б-роллы | вставки по словам, раскладки «весь экран» / «верх пол-экрана» (спикер уезжает вниз, субтитры на стык) | рендер ~1 мин |
| Текст за головой (опция) | маска человека RobustVideoMatting: стабильна во времени, без мебели, кроссплатформенная | ~3 мин на 10 с |
| Музыка | подложка по рецепту автора, собранная под длину рилса, конец в тихом месте трека, −12 LU к голосу | секунды |
| Склейка | ffmpeg: основа → маска (опционально) → передний слой → звук | ~1 мин |

Полный рилс 36 с — около 10 минут счёта на Apple Silicon. Без маски — около 5.

## Решения

### 1. Два скилла, граница по ритму жизни

- **`/reel`** собирает конкретный ролик из сырой записи. Вход — видео (+ отдельный звук). Выход — mp4 и снимок сборки.
- **`motion-assets`** ведёт библиотеку, которая живёт дольше одного ролика: моушн-сцены, обработанные б-роллы, оверлеи. Автор берёт ассеты и руками в монтажке, без `/reel`.
- `/reel` **выбирает** из библиотеки, но не рисует ассеты. Если подходящего ассета нет, в плане появляется строка «нет ассета → карточка или `motion-assets`», а ассет на лету не изобретается.
- `rough-cut` остаётся первой стадией `/reel` и самостоятельным скиллом.

### 2. `/reel` — конвейер с одним обязательным шлюзом

1. **Резка** — `rough-cut` целиком: звук монтажа, синхрон, тишина/дубли, стадия «Взгляд», отчёт.
2. **Расшифровка смонтированного** + словарь замен из настроек (кодовые слова, термины) + `snap_words.py`. Текст сверяется со сценарием, если он есть; расхождение показывается.
3. **План** — `PLAN.md`, таблица: время / слово / что появляется (карточка, ассет, б-ролл с точкой входа) / раскладка / наезд. **Шлюз: без «ок» автора рендера нет.** Правки плана — словами («на „сервере“ поставь терминал»).
4. **Слои** (HyperFrames, 1080×1920):
   - **основа** — спикер с наездами;
   - **вставки** — б-роллы и ассеты по плану, раскладки `full` / `half` / `overlay`;
   - **передний** — субтитры и карточки, прозрачный webm;
   - **задний** (опция «текст за головой») — подложка + крупный текст + маска человека.
5. **Склейка** + музыка + громкость (−14 LUFS голос, музыка −12 LU к голосу, true peak −1,5).
6. **Проверка** — контакт-лист по кадру на каждую вставку + чек-лист (раздел 7). Найденное правится до показа автору.
7. **Заморозка и порядок** — в `export/` ровно две папки: `final/` (только готовые ролики + README «что есть что») и `_сборка/` (проекты, слои, скрипты, cut-list, черновой монтаж, звук, снимок сборки финала без кадров). **Отбракованные варианты удаляются сразу**, как только автор выбрал; кадры и маски удаляются после того, как результат вшит в основу. В прототипе демо копились, и папка разрослась до тысяч файлов и 3,7 ГБ — автор отметил это как проблему.
8. **Правки** автора («субтитры закрывают лицо — ниже») записываются в `lessons.md` рядом с файлом настроек и читаются при каждом запуске, чтобы та же ошибка не повторялась в следующем ролике.

### 3. Режимы

| Режим | Что делает |
|---|---|
| `cut` | только `rough-cut` |
| `cut+subs` | резка + субтитры |
| `subs` | субтитры поверх уже смонтированного файла (автор монтировал сам) |
| `full` | резка, субтитры, вставки по плану, наезды, музыка |

Опции поверх режимов: `behind_text` (текст за головой с маской — по умолчанию выкл., приём дорогой и у автора разовый), `music` (вкл/выкл), `brolls` (папки), `zoom` (вкл/выкл).

### 4. Настройки живут вне скилла

Скилл обезличен. Всё личное лежит в файле настроек в рантайм-папке автора (`reel.settings.json` рядом с его студией), и скилл его читает:

- тема: цвета (фон тёмный/светлый, набор акцентов — сплошных и градиентов, с парами для светлого фона), шрифты с кириллицей (файлы);
- субтитры: стиль (`строки` / `по_слову`), появление слова (`приближение` 80→100% за 0,18 с / `без_анимации` / `волна`), размер, читаемость (размытая тёмная подложка под всем словом в цвете фона бренда: ~1,5 em шире по бокам, плотность ~0,6 у текста, края размыты — ореол по буквам автор не замечает);
- музыка: файл трека + рецепт (вход, цикл A–B, тихие зоны, где вокал) или готовая подложка;
- словарь замен для расшифровки (кодовые слова, имена, термины);
- CTA по площадкам (кодовое слово / ссылка в шапке);
- папки б-роллов и библиотеки ассетов;
- предпочтения: раскладки, уровни наезда, ударные слова, длина вставки.

Нет файла — скилл спрашивает минимум (тема, кодовое слово) и предлагает сохранить.

### 5. `motion-assets` — библиотека

**Структура:** папка библиотеки (вне репозитория и вне волта: видео в волте не храним) + `index.json`:

```json
{ "id": "tg-coin-flip", "kind": "scene|broll|overlay", "layout": "full|half|overlay",
  "duration": 3.3, "theme": "dark|light", "tags": ["telegram", "канал"],
  "describes": "глянцевый значок Telegram переворачивается, круги",
  "events": [{"t": 0.15, "what": "значок появляется"}, {"t": 1.75, "what": "переворот"}],
  "slots": {"headline": "текст", "accent_word": "слово"},
  "files": {"mp4": "…", "mov_alpha": "…", "green": "…", "preview": "…"} }
```

**Режимы:**
1. **Создать сцену** из шаблона со слотами (текст, число, иконка, скриншот) в теме автора.
2. **Обработать свой б-ролл:** опись событиями (ниже), кадрирование 9:16, наезд на место, выделение текста, ускорение пустот, размытие приватного.
3. **Оверлей:** значки, персонажи, логотипы на прозрачном фоне.

**Форматы выхода:** `full`/`half` — обычный mp4 (прозрачность не по умолчанию: автор и его референсы чаще перекрывают экран целиком или наполовину); `overlay` — `.mov` ProRes 4444 с альфой + `.mp4` на зелёном (хромакей в CapCut).

**Каталог шаблонов** (снят с референса автора, внешний вид — тема автора): кинетический заголовок по словам с акцентом и строкой-контекстом; иконка-«монета» с переворотом и кольцами; источники → бот; пост в 3D с полосой сканирования и печатью текста; табло с перелистыванием; счётчик с графиком; окно чата с печатью запроса и строками; телефон со скриншотом; таймлайн монтажки с вырезами; тумблер-метафора; «принтер» плана; карточка профиля с выделением ссылки; объёмная цифра шага. Фон — тёмный и светлый с плавающими размытыми словами.

**Планка качества** (отличие пробы от референса): объёмные иконки (отрисованное 3D, а не плоский значок), сквозные объекты, переходящие из сцены в сцену, и метафоры сложнее карточки.

### 6. Опись б-ролла — события, не темы

Опись делается один раз и хранится в `index.json`:

1. **Переходы автоматически:** разница соседних кадров (10 к/с, 108×192, серое) > 4 → переход/наезд (у записей экрана с авто-зумом их много). Вставки ставятся только на стоячие участки.
2. **События с шагом 0,5 с:** что появилось, что выделено, где клик, где объект виден целиком. По контакт-листам 2 к/с и точечным кадрам (перемотка `-ss` после `-i`, иначе кадр неточен).
3. **Приватность:** IP, ключи, токены, почты. В прототипе нашлись IP сервера в заголовке терминала и API-ключ целиком на 3 секунды вставки. Помечаются как запретные окна или размываются в копии; оригинал не трогается.

### 7. Правила монтажа (каждое — с выдачей, где его видно)

| Правило | Откуда | Где видно исполнение |
|---|---|---|
| Отдельная запись звука — звук монтажа | поправка автора | первая строка отчёта `Звук: <файл>` |
| Кусок начинается со взгляда в камеру | поправка автора | стадия «Взгляд» в отчёте `rough-cut` |
| Вставка на ключевое слово 0,5–1,8 с, буквально | монтаж автора | колонка «слово» в `PLAN.md` |
| Объект в кадре целиком (команда, ссылка, кнопка) | оценка автора | событие «виден целиком» в описи |
| Хук — сначала результат | монтаж автора | первые строки `PLAN.md` |
| Раскладки `full` / `half`, прозрачность — опция | поправка автора | колонка «раскладка» |
| Масштаб на склейке ≥ 0,1, «вжух» на ударном слове | привычка автора | колонка «наезд» |
| На `half` субтитры поднимаются на стык | прототип | проверка кадров |
| Текст за головой масштабируется ≤ 1,04 (иначе вылезает за край) | прототип | генератор наездов |
| Музыка кончается в тихом месте трека, не обрезом | прототип | сборщик подложки |

### 8. Проверка перед показом (чек-лист)

Кадр на каждую вставку + 30 кадров на окна с маской: кадр не на размытом переходе; объект целиком; субтитры не на лице; карточка не налезает на б-ролл; нет мебели/ореола в маске; ничего приватного; тексты совпадают со сценарием; первая и последняя секунды чистые.

## Технические решения и подводные камни

- **HyperFrames как движок,** но свой HTML: каталоговые стили латинские. Шрифты — локальные `@font-face` с кириллицей.
- **Seek-safe анимация** (рендер перематывает покадрово): только transform/opacity (`top`/`left` линтер запрещает); `fromTo` для элементов с CSS-трансформом; никаких `tl.call` с подменой текста — цифры табло лежат стопкой; селекторы по `id` (в атрибутных селекторах кавычки ломают скрипт); один `#root` с `data-composition-id`.
- **Наезд** — масштаб обёртки `.inner` вокруг `<video>`, центр — лицо (Vision, медиана по куску). Масштаб ≥ 1 вокруг точки внутри кадра — края всегда закрыты.
- **Маска человека:** u2net (бандл HyperFrames) захватывает кресло и кусок торшера; Apple Vision — почти без мебели, но только macOS; **RobustVideoMatting** — без мебели, стабильна во времени, CPU/MPS, любая ОС → по умолчанию. Последовательность кадров для ffmpeg должна быть сплошной (пропуски заполнять ссылками).
- **Взгляд и центр лица** сейчас — Apple Vision. Нужна запасная ветка ONNX для Linux/Windows (MediaPipe ставится тяжело, установка зависала).
- **Округление кадров:** первый кадр куска — `ceil(t·fps)+1`, а не `round`, иначе проверяется хвост прошлого куска.
- **Длительность композиции** брать из реального файла (`ffprobe`), а не из констант — после пересборки чернового всё съезжает.
- **Альфа-слои** — VP9 webm; при наложении ffmpeg декодировать `-c:v libvpx-vp9`.

## Что берём из прототипа

Скрипты в рабочей папке автора (вне репозитория), путь — в приватном приложении в студии:
- `build_layers.py` — субтитры по страницам + карточки + задний слой; флаги `CARDS_OFF`, `HALF`, `NO_PLATES`;
- `build_zoom.py` / `build_main.py` — наезды и вставки по плану (`INSERTS` по словам);
- `music_bed.py` — подложка под длину с концом в тихой зоне;
- `fix_transcript.py`, `rvm_matte.py`, `face_center.swift`, `composite.sh`;
- тестовая моушн-сцена `test-01` (4 шаблона).

Перенос в скиллы — с тестами чистых функций (план наездов, разбиение субтитров, подбор вставок по словам, сборка подложки), как у `rough-cut`.

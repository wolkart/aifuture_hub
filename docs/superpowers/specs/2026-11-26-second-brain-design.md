# second-brain — дизайн скилла

Дата: 2026-11-26. Источник решений — передача из волта автора («ПЕРЕДАЧА — скилл „Второй мозг“ для
клуба») и разговор 2026-11-26. План одобрен автором.

## Зачем

Человек говорит агенту одну фразу — и у него появляется второй мозг: папка заметок со структурой,
правила для агентов, каталог, правило «пиши в мозг» в общих инструкциях агентов на компьютере,
история в Git. По желанию — синхронизация через приватный GitHub и агент на сервере. Если у
человека уже есть волт Obsidian, агент переносит его в новую структуру.

Для кого: участники клуба AI Future Club (через пост «Рабочего сетапа» — третья часть фразы
установки) и все, кто заберёт скилл из публичного хаба. Продаём лёгкость входа: от человека на
базовом уровне — ничего, кроме фразы и ответов на несколько вопросов.

Почему скилл, а не часть кита: кит ставится на каждый проект, второй мозг — один раз на человека
и нужен не всем. Поэтому он рядом с `agent-memory`, по его образцу.

## Цели, не-цели, анти-цели

**Цели**
- Одна фраза → рабочий второй мозг на Маке или Windows (уровень 1).
- Любой агент на компьютере (Claude Code, Codex, OpenCode, Kimi) знает, где мозг, читает его
  каталог и сам дописывает туда медленное: новый проект, решение с «почему», вышедший результат.
- Уровень 2: приватный GitHub, фоновая синхронизация раз в 5 минут.
- Уровень 3: копия на сервере для агента (Гермес / OpenClaw).
- Переезд старого волта: машина раскладывает, человек отвечает только на спорное, ни одна заметка
  не теряется, ссылки не рвутся.
- Повседневные просьбы: «разложи входящее», «проверь второй мозг», «пересобери каталог»,
  «разбери конфликт», «верни заметку как было».

**Не-цели**
- Поиск по смыслу, эмбеддинги, базы данных, MCP-сервер для мозга. Мозг — папка Markdown + Git.
- Замена тяжёлого скилла obsidian-second-brain. Он остаётся дополнением для продвинутых; наши имена
  файлов с ним совместимы.
- Синхронизация памяти агента (`~/.agents/memory`) — это `agent-memory`, не мы.

**Анти-цели (провал, даже если технически работает)**
- Мозг зарастает ходом работы: статусами, шагами, «где остановились». Это память проекта.
- Человеку нужно что-то делать руками каждый день: раскладывать, коммитить, синхронизировать.
- Ключи или пароли попали в историю Git.
- Волт в облачной папке (iCloud, OneDrive, Яндекс.Диск, Dropbox) — облако ломает Git.
- В публичном хабе следы автора: его пути, имена, проекты.

## Ограничения

- Хаб публичный и обезличенный: в скилле только шаблоны и примеры.
- Mac и Windows на компьютере, Linux на сервере.
- **На Windows обычно нет Python** (у учеников есть Git и Node.js — урок «Ставим Node.js и Git»).
  Базовый уровень обходится без Python. Python нужен только для переезда и пересборки большого
  каталога; на Windows агент ставит его через `winget` с согласия человека.
- Агентам запрещено делать `git` в волте в обычной работе (правило волта). Исключения: установка,
  переезд и явные просьбы «разбери конфликт», «верни как было».
- Тот же закон, что и для остальных скиллов хаба: `SKILL.md` — только то, что нужно каждый раз;
  то, что нужно в особый момент, — в `references/` с явным «когда читать».

## Подходы

1. **Инструкция + шаблоны + скрипты только там, где без них нельзя** — как `agent-memory`.
   Агент ведёт разговор (вопросы, «Обо мне», карточки проектов, опись), копирует шаблоны;
   скрипты — для фоновой синхронизации и для работы с тысячами файлов (переезд, каталог).
   **Выбран.** Разговорная часть всё равно нужна, а детерминированное — в скриптах.
2. **Один скрипт-установщик** (`install.sh` / `install.ps1`), агент только запускает. Надёжнее
   на шаге «создать папки», но «Обо мне», проекты и опись всё равно делаются в разговоре, а
   установщик на две ОС — ещё два больших файла, которые надо держать в согласии. Отброшен.
3. **Поверх obsidian-second-brain** (`/obsidian-init` пишет правила и каталог). Отброшен
   решением 2026-11-26: тяжёлый (48 команд, хуки), `/obsidian-init` перечисляет в каталоге
   каждую заметку. Остаётся дополнением.

Ядро (правило «куда класть», быстрое и медленное, три вида фактов, карта папок, скрипты
переезда) уже проверено на волте автора. Через `meta-prompt` его не гоняем — только обезличиваем
и упаковываем (прецедент — `strategist`).

## Откуда переносим

Проверенные оригиналы лежат вне хаба, в волте автора и на его компьютере. Исполнитель переносит
их и обезличивает, с нуля не пишет:

| Что | Оригинал |
|---|---|
| Правила волта → `templates/vault/_CLAUDE.md` | `~/second-brain/_CLAUDE.md` |
| README для человека → `templates/vault/README.md` | `~/second-brain/README.md` |
| «Обо мне» → `templates/vault/About Me.md` | `~/second-brain/About Me.md` (только устройство разделов) |
| Карточка проекта | `~/second-brain/projects/*/<Проект>.md` |
| Раздел «Второй мозг» → `agents-block.md` | `~/.agents/AGENTS.md` |
| `index.py`, `cards.py` | `~/second-brain/_переезд/` |
| `inventory.py` ← `build.py` + `render.py`; `move.py`; `switch.py`; формат правил | `~/second-brain/_переезд/` (`rules.py` — образец формата) |
| `sync.sh` | `~/.local/bin/second-brain-sync.sh` (Мак), `/root/second-brain-sync.sh` на сервере (`flock`, `chown`) |
| launchd-задача | `~/Library/LaunchAgents/com.wolkart.second-brain-sync.plist` |
| Стиль текста для человека | `УСТАНОВКА.md` news-reposter (`~/Products/My Products/news-reposter/`) |

из хаба через `codeload.github.com` + `tar`), на Windows — `curl.exe` и `tar` в PowerShell.

## Уровень 1 — установка (SKILL.md)

Порядок шагов:

1. **Вопросы.** Четыре, по одному:
   - есть ли уже волт Obsidian или второй мозг (волт → `references/migration.md`, дальше по нему;
     второй мозг на GitHub с другого компьютера → ветка «Второй компьютер» ниже);
   - где хранить — по умолчанию `~/second-brain`;
   - нужна ли синхронизация через GitHub; есть ли сервер с агентом (это уровни 2 и 3);
   - в каких программах работаешь (чтобы подключить правило к каждой).
2. **Проверка места.** Путь не внутри облака: `~/Library/Mobile Documents`, `~/Library/CloudStorage`,
   папки с `Yandex.Disk`, `Dropbox`, `OneDrive`, `iCloudDrive`; на Маке не `~/Documents` и не
   `~/Desktop` (их может синхронизировать iCloud, а launchd без полного доступа к диску туда не
   ходит); на Windows не «Документы» (их часто забирает OneDrive). Попало — объяснить и
   предложить домашнюю папку.
3. **Шаблон.** Скопировать `templates/vault/` в выбранную папку. `AGENTS.md` — ярлык на
   `_CLAUDE.md` (Мак, Linux); на Windows — файл-указатель в одну строку «Правила — в `_CLAUDE.md`,
   прочитай его до работы» (ярлык без режима разработчика не создаётся, а копия разойдётся).
4. **Git.** `git init -b main`, `core.quotepath false`, на Маке `core.precomposeunicode true`, на
   Windows `core.longpaths true`; первый коммит «Второй мозг создан».
5. **Обо мне.** 5–7 вопросов, ответы → `About Me.md` по трём разделам: вечное (путь, чем
   занимается, стек), срезы с датой («на ГГГГ-ММ: …»), не утверждать. Вопросы: кто ты и чем
   занимаешься; путь — откуда пришёл, ключевые даты; инструменты и стек; на чём зарабатываешь или
   хочешь зарабатывать; цели на ближайшие месяцы; как с тобой говорить; что о тебе не утверждать.
   Цифра, которая меняется, — только с датой.
6. **Проекты.** «Какие у тебя сейчас проекты и где они лежат?» + предложение найти git-папки в
   домашней (глубина до 4, без `node_modules`, `Library`, `AppData`). Человек подтверждает
   список → карточка на проект по шаблону + строка в `index.md`. Репозитории не переносятся:
   карточка указывает, где проект живёт.
7. **Правило для агентов.** Раздел из `templates/agents-block.md` (с подставленным путём) → в
   `~/.agents/AGENTS.md`: нет файла — создать; есть раздел — заменить. Программы ещё не читают
   главный файл (нет ярлыков Codex/OpenCode) — подключить по шагу 3 скилла `agent-memory`
   (ссылка на его `SKILL.md`, текст не дублируем). Claude Code: в `~/.claude/CLAUDE.md` строка
   `@~/.agents/AGENTS.md`, если её нет; если в главном файле есть раздел «## Память» — рядом
   строка «Раздел „Память“ оттуда к Claude Code не относится: у него своя память».
8. **Фоновое сохранение.** `sync.sh` копируется в `~/.local/bin/second-brain-sync.sh` (обновление
   скилла не меняет работающую задачу на ходу); launchd-задача `local.second-brain.sync`,
   `StartInterval` 300, `RunAtLoad`, лог `~/Library/Logs/second-brain-sync.log`. Windows — по
   `references/windows.md`. Без GitHub задача только сохраняет историю на компьютере.
9. **Obsidian** (по желанию). Нет программы — предложить поставить (`brew install --cask obsidian`
   / `winget install Obsidian.Obsidian`) и открыть папку как хранилище.
10. **Проверка.** Новое окно агента в любом проекте: «что ты знаешь о моих проектах?» — ответ
    из карточек мозга. Через 5 минут в `git log` волта — коммит `auto: …`.

**Второй компьютер.** Мозг уже есть на GitHub: `gh repo clone` в папку вне облака (проверка
места — шаг 2), дальше шаги 7–10. Шаблон, «Обо мне» и проекты пропускаются — они уже в репозитории.

**Повторный запуск установки** на живом мозге ничего не затирает: `_CLAUDE.md` и `README.md`
волта — уже вещи человека. Шаблон новее — показать разницу и предложить перенести нужное. Раздел в
`~/.agents/AGENTS.md`, строка Claude Code и фоновая задача обновляются молча (они наши).

## Шаблоны — что в них

**`_CLAUDE.md`** — обезличенные правила волта автора, разделы те же:
- что это за база; второй мозг ≠ память проекта; быстрое и медленное; три вида фактов (вечный,
  с датой, ссылка; меняющаяся цифра без даты запрещена);
- сначала проверь живое состояние;
- куда класть — шесть вопросов, первый «да» решает (лично → `journal/`; нужно для проекта →
  `projects/<проект>/`, проверка «закроется проект — нужна ли заметка сама по себе?»; публикация
  → `content/`; чужое как есть → `raw/`; знание → `wiki/`; закончилось → `archive/`); не уверен —
  спроси одной строкой; инбокса нет, сырьё — в `raw/входящее/`, разбирает агент;
- карта папок; ключевые файлы; каталог держать коротким (большие папки — строкой);
- что писать без вопроса, что спросив; формат заметок; синхронизация (текст по уровню);
  не трогать (`journal/` только по прямой просьбе и никогда не цитировать в контенте; `raw/`
  неизменно; `archive/` только читать; `templates/`, `.obsidian/`).
- Обращение к владельцу — «человек» (как в `agent-memory`).

**`README.md`** — по образцу README волта автора: что это, где что лежит (таблица с примерами),
куда класть новое, как работает каждый день, если что-то пошло не так, уход раз в неделю, чего
не делать. Раздел про синхронизацию агент дописывает под выбранный уровень.

**`About Me.md`** — `aliases: [Обо мне]`; разделы «Вечное», «Срезы с датой — история, не для
текстов», «Не утверждать». Имя английское — по соглашению obsidian-second-brain (`/obsidian-world`
ищет `SOUL.md` / `About Me.md`).

**Карточка проекта** — свойства `date`, `updated`, `type: project`, `status`, `tags`,
`description`; разделы «Что это», «Где живёт», «Где смотреть статус», «Главное решено» (решения с
датой), метки раздела «Заметки проекта» (пересобирает `cards.py`).

**`agents-block.md`** — раздел «## Второй мозг»: что это и что это не память проекта; нужен
контекст шире папки — начни с `<путь>/index.md`, правила — `<путь>/_CLAUDE.md`; запиши сам без
просьбы только медленное (новый проект → карточка + строка в каталоге; решение с «почему» → в
карточку с датой; вышедший результат → в карточку со ссылкой); не туда — шаги, статус, «где
остановились»; Git в этой папке не трогай. Должен работать и без `agent-memory` («память проекта
и `PROGRESS.md`», без отсылок к соседнему разделу).

## Скрипты

Python — только стандартная библиотека, запуск `python3 -I <скрипт> <аргументы>`. Все пути
приводятся к NFC (Мак хранит «й/ё» разложенными). Скрипты не печатают содержимое файлов, где
могут быть ключи, — только пути и счётчики.

**`sync.sh <волт>`** (Мак и Linux):
- блокировка от одновременного запуска: `mkdir`-замок в `$TMPDIR`, протухший старше 15 минут
  снимается (на Маке нет `flock`);
- идёт ручной rebase/merge — пропуск;
- `git add -A`; есть изменения — коммит `auto: <дата время> · <хост> · файлов: N`;
- нет `origin` — конец (уровень 1);
- стоит отметка конфликта (`.git/second-brain-conflict`) — только локальный коммит, строка «стоит
  конфликт» в лог, без уведомления, выход;
- `git pull --rebase origin <текущая ветка>`; не вышло → `rebase --abort`, отметка конфликта,
  строка «КОНФЛИКТ» в лог, уведомление один раз (Мак — `osascript`), код 1; ничего не теряется.
  Отметку снимает просьба «разбери конфликт» — так человек не получает уведомление каждые 5 минут;
- `git push`; строка «ок» в лог;
- необязательный `--chown <uid:gid>` для сервера (файлы агента в контейнере).

**`sync.ps1 <волт>`** (Windows) — та же логика; замок — каталог в `%TEMP%`; уведомление —
всплывающее окно Windows из PowerShell; лог — `%LOCALAPPDATA%\second-brain-sync.log`.

**`index.py <волт>`** — обобщённый `index.py` автора:
- порядок разделов: Обо мне → Проекты (карточка первой, потом заметки по подпапкам) → Знания
  (строка на заметку) → Контент → Сырьё (строка на папку) → Дневник (одна строка без
  содержимого) → Архив (строка на папку) → Шаблоны;
- **большая папка — строкой**: в папке больше порога заметок (по умолчанию 30, флаг `--big N`)
  или папка `cards/` → одна строка «`путь/` — N заметок»;
- описание заметки: `description` → `тема` в свойствах → первый абзац после `## For future agent`
  → первая содержательная строка; до 140 знаков;
- одноимённые заметки — ссылка с путём (`[[путь/имя|имя (папка)]]`), иначе Obsidian свяжет одну;
- дата в свойствах — сегодняшняя.
- Ничего, что знает про разведку, курсы, AI Mindset и прочее конкретное у автора.

**`cards.py <волт>`** — как у автора: для каждой `projects/<П>/<П>.md` собирает ссылки на все
`.md` папки проекта, кроме самой карточки, сгруппированные по подпапкам (корень проекта —
первым), и пересобирает раздел «## Заметки проекта» между метками
`<!-- заметки проекта: начало (пересобирается скриптом второго мозга cards.py) -->` и
`<!-- заметки проекта: конец -->`; остальной текст карточки не трогает; меток нет — дописывает в
конец. Пусто — строка «Пока только карточка: материалы проекта живут в репозитории».

**`links.py <волт>`** — битые `[[ссылки]]` (выделено из `move.py` автора); печатает список, код
выхода = есть ли битые. Используют `move.py` (до/после) и «проверь второй мозг».

**`migrate/secrets.py <папка>`** — образцы ключей (`sk-…`, `sk-ant-…`, `ghp_`, `github_pat_`,
`xox[bpa]-`, `AKIA…`, `AIza…`, `-----BEGIN … PRIVATE KEY-----`, `api_key|token|secret|password
= …`) по тексту и по `.env*`; печатает `файл:строка:вид` и значение, замаскированное до 4 знаков;
заглушки (`sk-xxx`, `your_key_here`, `…`) помечает «похоже на заглушку». Решение по каждому
совпадению — глазами агента и человека.

**`migrate/inventory.py`** — две команды:
- `tree <волт>` — дерево папок с числом заметок и других файлов, по нему агент пишет правила;
- `build <волт> <rules.py>` — обобщённые `build.py` + `render.py` автора: правила (откуда — папка
  с `/` или путь/начало имени; куда; почему; вопрос к человеку) → `plan.json` + `Опись.md`
  (новая структура, итог по папкам, «вопросы к тебе», таблица); печатает файлы без правила,
  коллизии и заметки, ставшие одноимёнными.

**`migrate/move.py <волт> <plan.json> [--dry]`** — `move.py` автора без захардкоженного:
- старые верхние папки и замены в настройках Obsidian выводятся из правил, а не списком в коде;
- переименование, отличающееся только регистром (`bases` → `Bases`), — в два шага через
  временное имя (Мак не различает регистр);
- правка путей в `.md`, `.base`, `.canvas` и в папках настроек `.obsidian/*.json`;
- битые ссылки до и после, список новых битых.

**`migrate/switch.py --old <путь> --new <путь> [--plan plan.json] <файл>… [--dry]`** — пути к
волту в файлах вне волта; печатает только счётчики. Кандидатов находит агент поиском старого пути
по домашней папке (`.md`, `.env*`, `.json`, `.yaml`, `.toml`, `.py`, `.sh`, `.plist`; без
`node_modules`, `.git`, `Library/Caches`).

## Уровень 2 — GitHub (references/sync.md)

1. Нет `gh` — поставить с согласия (`brew install gh` / `winget install GitHub.cli`).
2. `gh auth login --web --git-protocol https` (человек жмёт в браузере), `gh auth setup-git`.
3. Перед созданием репозитория — спросить имя и подтверждение (это создаёт что-то снаружи).
   `gh repo create <имя> --private --source <волт> --push`; проверить
   `gh repo view --json visibility` = PRIVATE.
4. Фоновая задача уже стоит — с появлением `origin` она сама начинает отправлять. Проверка: через
   5 минут на GitHub свежий коммит, в логе «ок».
5. README волта — дописать раздел «Как убедиться, что всё работает» и «Если что-то пошло не так»
   (конфликт, откат, где лог).

Грабли: Мак во сне пропускает запуски — всё уходит в течение 5 минут после пробуждения (написать
в README волта); две синхронизации одновременно дают ложный конфликт — замок в скрипте.

## Уровень 3 — сервер (references/server.md)

Для тех, у кого уже стоит агент на сервере (урок про агентов на сервере). Порядок:
1. На сервере ключ развёртывания `ssh-keygen -t ed25519 -f ~/.ssh/second_brain_deploy -N ""`;
   публичную часть добавить в репозиторий с правом записи (`gh repo deploy-key add … --allow-write`
   с компьютера) — ключ только на этот репозиторий.
2. Git по SSH через `ssh.github.com:443` (исходящий 22 на серверах бывает закрыт): адрес
   `ssh://git@ssh.github.com:443/<владелец>/<репо>.git`, `core.sshCommand "ssh -i
   ~/.ssh/second_brain_deploy -o IdentitiesOnly=yes"`.
3. Клонировать в **новую** папку. Старую папку агента не переименовывать, пока клон не скачан
   (иначе агент без волта). Потом переключить путь агента на клон.
4. `sync.sh` в cron раз в 5 минут, лог в `/var/log/second-brain-sync.log`; агент в контейнере
   пишет от своего пользователя — `--chown <uid:gid>`.
5. Агент может считать чужой Git-репозиторий «только для чтения» по своей политике — в его
   инструкции явное исключение: «в папке второго мозга писать заметки можно, git не трогать».
6. Проверка: записать заметку с телефона через агента → через 5–10 минут она на компьютере.

Описание сверено с работающим сервером автора (адрес через 443, ключ в `core.sshCommand`, cron,
`chown` на пользователя контейнера).

## Переезд старого волта (references/migration.md)

Читается, только когда у человека уже есть волт. Порядок:
1. **Копия, не перенос.** Старый волт остаётся на месте (и в облаке), пока человек не решит.
   Копировать без `.trash/`, `.obsidian/workspace*.json`, файлов-конфликтов облака и без `.git`:
   если старый волт уже был в Git, его история остаётся в старой папке как архив, а у мозга
   начинается своя. Плагин Obsidian Git в копии выключить (его автосохранение и наша фоновая
   задача дали бы ложные конфликты).
2. **Ключи.** `secrets.py` → каждое совпадение глазами; настоящие — заменить заглушкой и сказать
   человеку перевыпустить ключ. Только потом Git: из истории ключ не удалить.
3. **Git, первый коммит = архив.** Коммит «Старый волт как был» + метка `old-vault-<дата>`.
4. **Биография.** Факты о человеке из старых заметок (профиль, позиционирование, «о себе») —
   в `About Me.md` до того, как они уедут в архив. Разошедшиеся цифры — в «Не утверждать».
5. **Опись.** `inventory.py tree` → агент пишет `_переезд/rules.py` по шести вопросам: правило
   на папку, исключения поштучно, пустое и дубли облака («(2)» в имени) — «не берём» (они
   остаются в метке-архиве). Спорное — с вопросом. `inventory.py build` → `Опись.md` → человек
   отвечает на вопросы → повтор до нуля вопросов.
6. **Перенос.** `move.py --dry` → `move.py`; новых битых ссылок быть не должно.
7. **Скелет.** Шаблонные файлы (`_CLAUDE.md`, `README.md`, `index.md`, карточки проектов) поверх
   новой структуры — как в уровне 1, шаги 3, 5–7.
8. **Пути вне волта.** Поиск старого пути по домашней папке, включая `.env` скиллов → `switch.py`.
9. **Каталог и карточки:** `index.py`, `cards.py`. Коммит «Переезд: новая структура».
10. **Дальше** — уровень 1, шаги 7–10, и уровни 2–3 по выбору. Старый волт убрать из облака —
    решает человек.

Папка `_переезд/` с описью и правилами остаётся в волте как история.

## Повседневные просьбы (SKILL.md)

- **«Разложи входящее»** — всё из `raw/входящее/` по шести вопросам; спорное — одной строкой
  человеку.
- **«Проверь второй мозг»** (раз в неделю) — `links.py`; заметки без ссылок; противоречия между
  заметками; меняющиеся цифры без даты; git-папки проектов без карточки; отчёт, правки — с
  согласия.
- **«Пересобери каталог»** — `index.py` и `cards.py`; на Windows без Python — вручную по тем же
  правилам или поставить Python.
- **«Разбери конфликт»** — синхронизация остановилась: `git pull --rebase` вручную, в спорной
  заметке сохранить обе версии текста, показать человеку, завершить rebase и отправить.
- **«Верни заметку как было вчера»** — `git log` по файлу → нужная версия → восстановить →
  коммит.
- **«Запиши во второй мозг …»** — по правилу «куда класть».

## Windows (references/windows.md)

- Скачать скилл: `curl.exe` + `tar` в PowerShell.
- `AGENTS.md` в волте — файл-указатель вместо ярлыка.
- Фоновая задача: `Register-ScheduledTask`, запуск при входе и повтор каждые 5 минут
  бесконечно, `powershell.exe -NoProfile -ExecutionPolicy Bypass -File …\sync.ps1 <волт>`.
  **Окно консоли не должно мелькать**: запуск через `conhost.exe --headless`, запасной вариант —
  обёртка `.vbs` через `wscript.exe`. Какой работает — проверить на живой машине.
- `.gitattributes` с `* text=auto eol=lf`: Мак и Windows не спорят о концах строк.
- Python — только для переезда и большого каталога, `winget install Python.Python.3.12` с
  согласия.
- Проверка места: «Документы», перенаправленные в OneDrive.

## Проверка

- **pytest** на сгенерированном «грязном» волте во временной папке: имена в NFD, `bases`/`Bases`,
  дубли «(2)», одноимённые заметки в разных папках, ссылки, `.base` с фильтром по папке,
  `.obsidian/app.json` с папкой вложений, настоящий на вид ключ и заглушка. Проверяются:
  `inventory build` (без правила, коллизии, одноимённые), `move` (перенос, регистр, пути в тексте,
  ноль новых битых ссылок), `switch` (счётчики), `index` (большая папка строкой, ссылка с путём),
  `cards` (повторный запуск ничего не меняет), `secrets` (находит ключ, заглушку помечает).
- **`sync.sh`** на временных репозиториях с «голым» репозиторием вместо GitHub: только сохранение
  без `origin`; отправка; второй запуск при занятом замке — пропуск; конфликт → код 1, rebase
  отменён, обе стороны целы.
- **Windows-скрипты** — на Windows-машине GitHub Actions (`.github/workflows/second-brain-windows.yml`,
  запуск по изменениям в `skills/second-brain/**` и вручную): `sync.ps1` по тем же сценариям,
  регистрация задачи в Планировщике, Python-скрипты.
- **Живые прогоны** (свежее окно агента, фраза из README):
  1. пустая папка на Маке, уровень 1 — во временной домашней папке и с отдельным именем
     launchd-задачи, чтобы не задеть настоящий мозг автора; после — убрать;
  2. уровень 2 — тестовый приватный репозиторий (создать и удалить — с согласия автора);
  3. переезд — на копии старого волта автора из метки `old-vault-2026-11-26` во временной папке;
     сравнить с тем, что получилось у автора вручную (раскладка по верхним папкам, число новых
     битых ссылок). В хаб из этой копии ничего не попадает;
  4. Windows вживую — мелькает ли окно, приходит ли уведомление. Машина у автора есть, но
     проверка не сейчас: до неё Windows-часть выходит с пометкой «проверено автоматически»,
     живая проверка — пунктом в `BACKLOG.md`;
  5. уровень 3 — сверка `server.md` с живым сервером, без изменений на нём.

## Мои решения (не обсуждались — проверить)

1. `Logs/` и `log.md` в базовый шаблон не входят: каждое изменение уже есть в истории Git со
   временем, а лишняя обязанность агента — правило без следа. Дополнение obsidian-second-brain
   заводит их само.
2. Формат заметок проще, чем у автора: свойства `date`, `type`, `tags`, `description` (одна
   строка — что внутри; её читает каталог). `ai-first` и `## For future agent` не обязательны;
   `index.py` понимает оба формата.
3. Раздела «Проекты сейчас» в `_CLAUDE.md` нет: список проектов один — в `index.md`, иначе два
   списка разойдутся.
4. Шаблон заранее настраивает Obsidian: вложения в `files/`, шаблоны в `templates/`, новые
   заметки, созданные руками, — в `raw/входящее/` (их разложит агент).
5. Фоновая задача стоит и на уровне 1 — только сохраняет историю, без GitHub.
6. Скрипт синхронизации копируется в `~/.local/bin`, а не запускается из папки скилла.
7. `AGENTS.md` на Windows — указатель, не копия.
8. На шаге «Проекты» агент предлагает найти git-папки в домашней — так мозг знает проекты сразу.
9. GitHub Actions для Windows-проверок — новая папка `.github/` в хабе.
10. После конфликта синхронизация встаёт (отметка в `.git`), уведомление приходит один раз;
    локальное сохранение продолжается.
11. Ветка «Второй компьютер» и правило «повторная установка не затирает правила и README волта».
12. Старый волт в Git: история остаётся в старой папке, у мозга своя; плагин Obsidian Git в
    копии выключается.
13. Правила описи — `rules.json`, а не `rules.py` автора: правила, написанные агентом, не
    исполняются как код. Поиск ключей — `scan_keys.py`, а не `secrets.py`: имя перекрыло бы
    стандартный модуль Python `secrets`.
14. Чужие незакоммиченные правки в рабочей папке (reel, motion-assets, reels-script, BACKLOG) в
    ветку не попадают: коммитятся только файлы скилла, спека и каталогов хаба.

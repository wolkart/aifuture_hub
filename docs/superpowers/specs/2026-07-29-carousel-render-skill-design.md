# Спека: скилл `carousel-render`

**Дата:** 2026-07-29
**Статус:** согласовано, готово к плану
**Заменяет:** `docs/spec-carousel-render.md` (черновик от 2026-07-29, написан до сверки с реальными карточками автора)

---

## 1. Что строим

Скилл `skills/carousel-render/`: на вход `slides.json` и тема, на выход — папка готовых PNG 1080×1350, залитых в стиль автора. Ноль ручной вёрстки, повтор на следующей карусели — ноль работы.

Технология: **HTML + CSS → headless Chrome → PNG.** Без внешних сервисов, без API-ключей, без новых зависимостей.

### Чего не делать (решено, не пересматривать)

- **Не Figma MCP.** Он строит по одному узлу за вызов: карусель на 9 слайдов — сотни вызовов, любой может лечь, текст всё равно едет. Он хорош читать чужой макет и точечно править, а не собирать с нуля. Предыдущий подход через мостик описан в `docs/figma-карусели-гайд.md` — этот скилл его заменяет для генерации; гайд после приёмки пометить как legacy.
- **Не генеративные картинки для карточек с текстом.** Модель врёт буквы (особенно кириллицу), не держит сетку, выдаёт девять разных стилей подряд. Генерация — только для ассетов, которые делаются один раз и переиспользуются.
- **Не автоподгонка кегля «лишь бы влезло».** См. §7: кегль ходит по конечным ступеням, ниже минимальной скилл ругается, а не сжимает.

## 2. Проверено на машине автора (не перепроверять)

- **Chrome стоит:** `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. `sips` на месте.
- Рабочая команда, снимает ровно заданный размер, кириллица рендерится:
  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
    --headless --disable-gpu --hide-scrollbars \
    --force-device-scale-factor=2 --window-size=1080,1350 \
    --screenshot=out.png "file:///абсолютный/путь/slide.html"
  ```
- **Качество:** рендерить с `--force-device-scale-factor=2` (2160×2700), затем ужимать `sips -z 1350 1080 file.png`. Текст заметно чище прямого 1x.
- **Шрифтов Oswald и Montserrat в системе НЕТ** — ни в `~/Library/Fonts`, ни в системных. Они живут только внутри Figma. Значит headless Chrome их не найдёт и свалится в засечный фолбэк. Оба — Google Fonts под OFL: скачиваются в папку темы и подключаются через `@font-face` файлом. **Проверить визуально на первой же карточке.**
- Playwright-браузеры в кэше есть, но не нужны. Node v24 и python3 есть.

## 3. Архитектура

Три части с разной ответственностью.

**Тема** (`theme.json`, вне репозитория) — все переменные: градиенты, цвета, шрифты с весами на каждую роль, пути к ассетам, блоки обвязки под IG и LinkedIn, ступени кегля. Единственное, что правит автор, когда меняет внешний вид. Инверсия «светлая обложка / тёмные буквы» — просто второй файл темы.

**Лейауты** (HTML + CSS, в репозитории) — четыре шаблона. Композиция зашита в код, из темы приходят только значения. Поэтому карусель не может разъехаться от слайда к слайду.

**Рендер** (скрипты) — собирает HTML из темы и `slides.json`, снимает Chrome, ужимает, проверяет переполнение, складывает PNG и контактный лист.

Граница «данные vs код» проведена сознательно: **меняются только переменные, композиция лейаутов фиксирована.** Свои HTML/CSS-шаблоны автор не дописывает — это цена за гарантию единообразия.

Логика живёт в скриптах, а не в промпте `SKILL.md`. Причина не архитектурная мода, а пункт приёмки: «правка одной строки в JSON меняет только эту карточку, остальные байт в байт». Побайтовая воспроизводимость требует детерминированного кода. `SKILL.md` остаётся оркестрацией.

|---|---|

| Бейдж «ЛИСТАЙ» на тёмном | `#E8E7EB` |
| Бейдж «ЛИСТАЙ» на светлом | кружок `#33336F`, текст `#F7F6FF` |

### Шрифты

- **Обложка целиком — Oswald Bold**: и заголовок, и подзаголовок под ним. Оба узкие, это не Montserrat.
- **Всё остальное — Montserrat**: тело, тело-список, CTA, подпись, бейдж. Вес плавает по месту (Black / Bold / Medium / Regular / Light).

## 5. Контракт `slides.json`

```json
{
  "meta": { "название": "Агент. Харнес. Loop.", "площадка": "LI", "тема": "volkov-dark" },
  "слайды": [
    { "№": 1, "лейаут": "обложка",
      "заголовок": "Агент.\nХарнес.\nLoop.",
      "подзаголовок": "Звучит как высшая математика. Внутри — три простые штуки. Объясняю." },

    { "№": 3, "лейаут": "тело",
      "блоки": [
        "Мозг, который только **болтает**",
        "Попроси ChatGPT собрать сайт. Он выдаст код и **замолчит**.",
        "**Дальше ты:** скопировал, вставил, запустил, поймал ошибку, пошёл спрашивать снова.",
        "А теперь смотри"
      ],
      "нить": true },

    { "№": 7, "лейаут": "CTA",
      "блоки": [
        "Хочешь разбираться в AI без магии и хайпа — подписывайся.",
        "Разбираю по-честному, как оно устроено на самом деле."
      ] }
  ]
}
```

Решения, зашитые в схему:

**Выделение — один маркер `**…**`, смысл подставляет лейаут.** В теле — жирное начертание Montserrat. На обложке — акцентный `#D97757` поверх синего заголовка. Автору не надо помнить, где какой цвет: он пишет «выделить», карточка знает, чем выделяют в этом месте.

**`\n` в заголовке — принудительный перенос.** «Агент. / Харнес. / Loop.» разбито осмысленно, это часть удара, автопереносу не отдаётся.

**`нить: true` — стрелка `⇢` в конце последнего блока.** Приём из `carousel-backbone`: поле, а не символ в тексте — стрелка рисуется элементом и всегда одинаковая.

**Обвязка (бейдж «ЛИСТАЙ» и подпись с аватаркой) рисуется сама.** В JSON про неё ни слова — это тема и лейаут. На `CTA` бейджа нет, а подпись рисует сам лейаут: крупнее обычного и сверху по центру, а не мелко внизу (§6).

**`площадка` в `meta` выбирает блок обвязки**: IG — хэндл одной строкой и своя аватарка; LI — имя с должностью в две строки и своя аватарка. Больше от площадки не зависит ничего.

## 6. Лейауты

Строгий словарь из четырёх значений. Расширять внутри карусели нельзя.

### `обложка`

Тёмный фон, крупный заголовок Oswald `#6695F1` с выделениями `#D97757`, под ним подзаголовок белым Oswald. Три вида:

| `вид` | Что рисует |
|---|---|
| `текст` (по умолчанию) | Только типографика |
| `декор` | То же + спарк (SVG) в свободном углу |
| `фото` | Фото на весь кадр, текст внизу поверх затемнения; поле `низ` — мелкая строка под текстом («СОХРАНИ, ЧТОБЫ НЕ ПОТЕРЯТЬ») |

При `вид: фото` **подпись с аватаркой гасится автоматически** — автор уже на фото, дублировать нелогично. Перебивается полем `"подпись": "показать"`.

```json
{ "№": 1, "лейаут": "обложка", "вид": "фото", "фото": "beach.jpg",
  "заголовок": "У **Claude** есть ADHD-режим, который взламывает твой **дофамин**. **За 4 часа** закроешь недельный список задач",
  "низ": "СОХРАНИ, ЧТОБЫ НЕ ПОТЕРЯТЬ" }
```

### `тело`

Светлый фон, 1–4 абзаца Montserrat `#33336F`, блок отцентрован по вертикали. Инлайновые `**…**` — жирное начертание. `нить: true` вешает `⇢` в конец последнего абзаца.

### `тело-список`

Светлый фон. Структура: заголовок → подзаголовок-боль → список пунктов `**имя** — что даёт` → подвал курсивом со стрелкой.

```json
{ "№": 4, "лейаут": "тело-список",
  "заголовок": "Разработка",
  "подзаголовок": "Проект не разваливается на пятой правке.",
  "пункты": [
    "**superpowers** — не бросишь на середине: сам разбивает работу на шаги и проверяет себя",
    "**context7** — код заводится с первого раза, а не «библиотека уже так не работает»"
  ],
  "подвал": "→ Твой отдел разработки" }
```

Отдельный лейаут, а не абзацный: ритм отступов между пунктами и подвал курсивом иначе пришлось бы имитировать руками на каждой карточке.

### `CTA`

Тёмный фон (тот же градиент, что обложка). Сверху по центру — аватарка, имя и должность крупнее обычного. Ниже — текст белым Montserrat по центру. Бейджа «ЛИСТАЙ» нет.

## 7. Типографические ступени и контроль переполнения

**Кегль — не свободная величина, а ступень из темы.** Автор и сам меняет размер руками: заголовок «АГЕНТ. ХАРНЕС. LOOP.» набран заметно крупнее, чем «Я ОТДАЛ СВОЙ INSTAGRAM CLAUDE»; списочная карточка мельче абзацной. Скилл делает то же, но дискретно.

- Для каждого лейаута в теме задан **конечный набор ступеней** (ориентир — три).
- Скилл выбирает ступень **по фактическому объёму контента и по лейауту**: список нормально читается мельче, чем абзацы, потому что глаз идёт по вертикали.
- Точные значения ступеней **снимаются с эталонных карточек автора** — он подбирал их глазами и они работают. Это и есть главная причина, по которой нужны эталоны: не подстроиться под одну карусель, а вытащить из неё типографику в числа.

**Проверка переполнения (обязательно).** После сборки каждого слайда проверить, влез ли контент в 1080×1350 — сравнить `scrollHeight` с высотой вьюпорта либо выставить флаг из страницы в `document.title`.

Не влезло даже на минимальной ступени — **не ужимать молча**, а вернуть внятное: «слайд 4: текст не помещается, сократи примерно на 18 символов». Автоподгонка «лишь бы влезло» — ровно то, из-за чего лента выглядит рвано; узнаваемость дороже удобства.

Второй рубеж, а не первый: `carousel-script` уже держит длину правилом fits-card из `slide-spec.md`. Текст приходит отмеренным по словам, `carousel-render` проверяет фактически по пикселям.

## 8. Изображения

Четыре слота.

| Слот | Уровень | Поведение |
|---|---|---|
| Аватарка автора | тема, своя на каждую площадку | Круглая, в подписи |
| Лого / спарк | тема | SVG; одноцветный перекрашивается из темы, второй файл под тёмный и светлый фон не нужен |
| Фон-картинка обложки | слайд | На весь кадр с затемнением под текст, `object-fit: cover` |
| Фото/скрин на слайде | слайд | Лежит рядом со `slides.json`, путь относительный |

**SVG предпочтителен растру:** вставляется прямо в разметку, масштабируется без мыла на любом кегле, перекрашивается через `currentColor`, не тянет внешних запросов. Растр тоже поддерживается.

Скилл картинки **не генерит** — только раскладывает. Ассета нет — рисует плейсхолдер и пишет об этом в отчёте.

## 9. Обезличенность и размещение

Правило хаба: личное не утекает в публичный репозиторий.

- В репозитории — скрипты, лейауты и `themes/example.json` с нейтральными цветами и системными шрифтами.
- Тема автора (цвета, шрифты, аватарки, спарк, хэндлы) — **вне репозитория**, путь в `.env` через `THEME_PATH`, по образцу `instagram-analytics`. В `.gitignore` — `.env` и `themes/local*`.
- Выходная папка — из `.env` (`OUTPUT_DIR`), дефолт рядом со `slides.json`.
- Шрифты скачиваются в папку темы один раз.

## 10. Выход, отчёт, использование

**Выход:** папка карусели — `01.png … 09.png` в 1080×1350 плюс `contact-sheet.png` (все слайды одной простынёй, чтобы автор проверил ритм одним взглядом).

**Отчёт** — короткий, без рассуждений: сколько снято и куда положено; какие слайды сели на пониженную ступень кегля; что не влезло даже на минимальной и на сколько символов резать; каких ассетов не нашлось.

**Вызов:**
```
/carousel-render <путь к slides.json>
```
или из контентной сессии: «отрендери карусель <название>» — скилл находит `slides.json` рядом с артефактом в волте.

## 11. Стык с `carousel-script`

Сейчас `carousel-script` отдаёт per-slide спек markdown-таблицей. Парсить markdown хрупко.

**Добавить в `carousel-script` раздел «Рендер-контракт»:** вместе с таблицей скилл кладёт `slides.json` по схеме §5. Таблица остаётся для человека, JSON — для рендера. Поля таблицы (`№`, `роль`, `заголовок`, `текст`, `подача`, `лейаут`) маппятся в JSON, плюс структурные поля под конкретный лейаут (`блоки`, `пункты`, `подзаголовок`, `подвал`, `нить`).

Словарь лейаутов в `slide-spec.md` привести в соответствие: `обложка`, `тело`, `тело-список`, `CTA`.

## 12. Приёмка (Definition of Done)

Четыре реальные карточки автора закрывают все лейауты и обе площадки:

1. **LinkedIn «Агент. Харнес. Loop.»** целиком — `обложка` + `тело` + `CTA`, подпись с именем и должностью. 7 PNG ровно 1080×1350, визуально совпадает с оригиналом.
2. **IG-карточка «Разработка»** — `тело-список` и IG-обвязка (подпись слева внизу).
3. **IG-обложка «Я отдал свой Instagram Claude»** — акцент `#D97757` и спарк.
4. **Пляжная обложка** — фото на весь кадр, подпись погашена автоматически.

Плюс:

5. Шрифт правильный — Oswald на обложках, Montserrat в теле, **не засечный фолбэк**.
6. Правка одной строки в `slides.json` и повторный прогон меняют только эту карточку, остальные байт в байт.
7. Слайд с заведомо длинным текстом ловится проверкой переполнения и попадает в отчёт, а не уезжает молча.
8. Скилл добавлен в каталог `skills/README.md`, прогнан `skills/install-skills.sh`, в `carousel-script` добавлен раздел «Рендер-контракт».
9. `docs/figma-карусели-гайд.md` помечен как legacy с одной строкой, куда идти вместо него.

## 13. Открытые вопросы (решаются на приёмке)

**Позиция обвязки дрейфует между карточками.** На LinkedIn бейдж «ЛИСТАЙ» сверху по центру и подпись внизу по центру. На IG-обложке бейдж сверху, подпись внизу слева. На IG-«Разработке» подпись внизу слева, а бейдж уехал вниз справа. Похоже на естественный дрейф между карточками разных дней, а не на замысел.

Позиция заложена как настройка темы на связку «площадка × лейаут», дефолты снимаются с этих карточек. На приёмке автор смотрит глазами и решает, где привести к одному виду.

**Ассеты, которых пока нет на руках:** аватарка IG, аватарка LinkedIn, спарк в SVG. Нужны к моменту сборки, дизайн не блокируют.

## 14. Вне объёма

- Веб-интерфейс, десктопное или мобильное приложение. Обсуждалось и **сознательно отложено**: сейчас делается скилл.
- Генерация картинок.
- Собственные HTML/CSS-лейауты сверх словаря.
- Лейауты `большая-цифра`, `цитата`, `сравнение`, сетка 2×3 и фигурки-маскоты из первого черновика спеки — автор их не выпускает. Сетка 2×3 была придумана, а не снята с практики: реальная карточка «команда из 42 помощников» оказалась вертикальным списком без картинок.

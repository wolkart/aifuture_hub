# HyperFrames: что ломает рендер

Читать, когда правишь HTML слоя руками или рендер упал/вышел не тем.

Слои собираются скриптами в обычные проекты HyperFrames (`index.html` +
`assets/` с GSAP и шрифтами). Версия CLI зафиксирована в `scripts/hf.py`
(`HF_VERSION`) — обновлять осознанно: от версии зависит, как рендер перематывает
таймлайн. Команда: `npx --yes hyperframes@<версия> render <папка> --output <файл>
--format webm|mp4 --fps 30` (webm — с прозрачностью).

## Почему свой HTML, а не каталог

Каталоговые стили субтитров (`embedded-captions`) — латинские шрифты, DNA под
16:9. Кириллица там рисуется фолбэком. Поэтому шрифты — локальные `@font-face`
из темы автора (в CSS — `var(--main)`, `var(--display)`).

## Seek-safe

Рендер перематывает таймлайн к каждому кадру, а не проигрывает его. Поэтому:

- анимировать только `transform`, `opacity`, `filter`, цвет; `top`/`left`
  линтер запрещает;
- `fromTo` для элементов с CSS-трансформом (иначе стартовое состояние берётся
  из уже сдвинутого);
- никаких `tl.call` с подменой текста — смена цифр табло делается стопкой
  элементов и прозрачностью;
- селекторы по `id`: в атрибутных селекторах кавычки ломают скрипт;
- один `#root` с `data-composition-id`, длительность — из реального файла
  (`ffprobe`), не из констант: после пересборки чернового всё съезжает;
- детерминизм: без `Math.random`, `Date.now`, сети.

## Наезд

Масштаб — у обёртки `#cam` вокруг `<video>`, центр — лицо (медиана по куску,
`faces.csv`). Масштаб ≥ 1 вокруг точки внутри кадра — края всегда закрыты.

## Альфа и склейка

Прозрачные слои — VP9 webm. При наложении ffmpeg декодер задаётся явно
(`-c:v libvpx-vp9` перед `-i`), иначе встроенный декодер теряет альфу. Кадры
маски — сплошная последовательность (дыры заполняются ссылкой на пустой кадр),
первый кадр куска — `ceil(t·fps)+1`.

## Замеры (Apple Silicon, ролик 36 с)

Передний слой ~1 мин 20 с, основа с 24 б-роллами ~1 мин 30 с, склейка с
громкостью ~40 с, маска RVM ~3 мин на 10 с.

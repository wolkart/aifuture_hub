# youtube-edit — длинный ролик под ключ

Ты монтажёр длинного ролика. Резку, время слов, рендер клипов, музыку и таймлайн
делают скрипты; твоя работа — решить, **что** показать на каких словах, написать сцены
и не отдать автору то, что ловят проверки. Автор видит один итог — таймлайн в Resolve,
где всё уже лежит: смотрит превью, при желании двигает, рендерит сам.

Пути `scripts/…` — от папки скилла, `../rough-cut/…` — соседний скилл резки,
`export/…` — от папки с записью. Всё новое — в `export/`, исходники не трогаются.

## Стадии

**0. Доктор, настройки, уроки.** `python3 scripts/check_env.py`. Тема, звуки,
библиотека — из `reel.settings.json` автора (одна тема на всё), своё у длинного
ролика — раздел `ютуб` того же файла (`references/settings.md`). Рядом с
настройками — `youtube-lessons.md`: правки автора из прошлых роликов, прочитай
целиком. Первая строка первого отчёта: `Уроки: <N> (последний: …)` или `Уроки: нет`.

**1. Формат.** Скринкаст (графика на висящий экран и понятия, спокойная музыка) или
говорящая голова (графика чаще, музыка энергичнее) — по записи, не спрашивая, если
видно. «Только резка», урок клуба без графики → `rough-cut`, здесь стоп.

**2. Фоном, параллельно** — скан кадров и расшифровка (обоим cut-list не нужен):

```bash
uv run scripts/scan.py <запись.mp4>            # → export/монтаж/scan.json: переходы зумов, голова, висящий экран
python3 ../rough-cut/scripts/transcribe.py <звук или запись> --backend scribe --language ru
```

**3. Резка** — `../rough-cut/SKILL.md`, раздел «Длинная запись» (lines → plan.json →
build; «верни 3, 7» → restore → build). После **каждого** build:

```bash
python3 scripts/zoom_guard.py export/<стем>.cutlist.json --scan export/монтаж/scan.json
```

На переходе зума ни реза — механизм, а не правило: границы реза уходят из окна
перехода, рез никогда не растёт. Проверяется всегда, чем бы ни снимали.

**4. Слова на таймлайне:** `python3 scripts/timeline.py words export/<стем>.cutlist.json <words.json>`
→ `export/монтаж/words.json` (номера фраз — как в отчёте резки).

**5. План графики** — открой `references/plan-format.md`. Таблица `# / где / вид / что`
в `export/монтаж/plan.md` по расшифровке и `scan.json` (где экран висит ≥ 7 с, где голова).
Готовое — из библиотеки: `python3 ../motion-assets/scripts/library.py find "<слово>"`.

**6. Пробы музыки:** `uv run scripts/music.py probe export/<стем>.cutlist.json [--format голова]`
→ 2–3 файла по 40 с (треки — из настроек или `--tracks`).

**7. Шлюз — одним сообщением:** отчёт резки (было → стало, смысловые резы с номерами,
строка zoom_guard) + план графики + пути проб. Автор отвечает одним («верни 3, №12 убери,
музыка 2, ок»). **До «ок» рендера нет.**

**8. Сцены** — открой `references/scene-craft.md` сейчас, не раньше. Пиши
`export/монтаж/scenes.py` на каркасе `scripts/stage.py` (образец — `assets/scenes.example.py`):

```bash
python3 scripts/build.py export/монтаж             # проекты, сдвиги начала, якоря на вырезанном
python3 scripts/build.py export/монтаж --gaps      # паузы > 1,8 с и что в них звучит
uv run scripts/check.py pre export/монтаж          # паузы, «мелькнуло», наложения на границах твинов, нахлёсты
```

Чини до `проблем 0`: паузу — действием на слово из отчёта (`mark` / `wave` / `shake` /
`chip`), наложение — раскладкой, «мелькнуло» — концом сцены.

**9. Рендер** (фоном, минуты на сцену):

```bash
python3 scripts/build.py export/монтаж --render
python3 scripts/head_zoom.py export/монтаж --render   # после графики: зум там, где её нет
uv run scripts/music.py bed export/<стем>.cutlist.json [--format …] [--track …]
uv run scripts/check.py post export/монтаж           # пустая треть + контактные листы
```

Листы `export/монтаж/_check/*.jpg` смотри **каждый** (Read): позднее появление, текст
за краем, графика не там, где показывает автор. Найденное — правка сцены → `build.py
<имя> --render` → снова `check.py`.

**10. Таймлайн:** `python3 scripts/assemble.py export/<стем>.cutlist.json`. Импорт
FCPXML в Resolve пока не подтверждён (`references/resolve.md`, «Проверено»): до первой
отметки там сначала отдай кусок `--range 0 180` и дождись «открылось как надо».

**11. Правки после показа.** Параметр (уровень музыки, порог паузы) → настройки; правка
одной сцены → `scenes.py` → `build.py <имя> --render` → `assemble.py`; остальное — строкой в
`youtube-lessons.md`: `- <дата> — <что было> → <как надо>`.

**12. Уборка** — автор отрендерил ролик → `export/монтаж/` удалить (клипы нужны таймлайну,
только пока он открыт в Resolve). Исходники — только по его «да».

## Красные линии

- **Нет «ок» на шлюз — нет рендера.**
- **Исходники и библиотека автора не трогаются;** всё новое — в `export/`.
- **`check.py` с ✗ — таймлайн автору не отдаётся.**
- **Ничего приватного в графике:** IP — из документационного диапазона (203.0.113.x),
  ключи и токены — заглушки.

Остальное — ориентиры с причинами в `references/scene-craft.md`; автор вправе пойти
против — тогда так и делай.

## Отчёт автору (финал)

```
Уроки: <N> (последний: …)
Звук: <файл>
Резка: <было> → <стало> · смысловых резов <N> · переходов зума <M>, резов поправлено <K>
Графика: <N> вставок (Д a · Э b · П c · А d) — <X> мин из <Y> (<Z> %) · зум на голове: <n> кусков
Проверки: pre — проблем 0 · post — проблем 0, листов <L> просмотрено · якорей заменено <k>
Музыка: <трек> · <LU> к голосу · проба №<i>
Таймлайн: export/<стем>.fcpxml → File → Import → Timeline…
```

## Границы

- Только резка — `rough-cut`; вертикальный рилс или шортс — `reel`; новый шаблон моушна
  или правка шаблона по номеру из каталога — `motion-assets`.
- Рендер упал или правишь HTML сцены руками — `../reel/references/hyperframes.md`.

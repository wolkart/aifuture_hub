# agent-memory — память агента между сессиями

Воспроизводит механику памяти Claude Code для любого агента, который умеет читать
и писать файлы: глобальное хранилище заметок, разбитое по проектам; индекс тем на
проект; индекс грузится в сессию всегда, заметки — по требованию.

Эффект: новая сессия продолжает работу так, как будто предыдущая не прерывалась —
агент видит, что решили, что отвергли и почему, и не предлагает отвергнутое заново.

## Устройство

```
~/.agents/
├── AGENTS.md              # глобальный указатель (блок «Память»)
└── memory/
    ├── <проект>/          # ключ = имя корневой папки проекта
    │   ├── MEMORY.md      # индекс тем проекта (шаблон: templates/MEMORY.md)
    │   └── <тема>.md      # заметки (шаблон: templates/note.md)
    └── _general/          # кросс-проектные темы; автоматом не грузится,
                           # читается по прямой отсылке
```

Для Claude Code указатель вместо `~/.agents/AGENTS.md` ложится в `~/.claude/CLAUDE.md`
(глобально) — механика та же.

Хранилище вынесено из проектов намеренно: ни одного лишнего файла в репозитории,
ничего не надо прятать в `.gitignore`, приватные заметки физически не могут
утечь в публичный репозиторий.

## Установка с нуля («поставь память»)

1. Создать папку `~/.agents/memory/`, если её нет.
2. В глобальном инструкционном файле агента (`~/.agents/AGENTS.md`, у Claude Code —
   `~/.claude/CLAUDE.md`; файла нет — создать) добавить блок «Память»:

```markdown
## Память

Долгая память лежит в `~/.agents/memory/<проект>/`, где `<проект>` — имя корневой
папки текущего проекта.

- В начале работы проверь, есть ли `~/.agents/memory/<проект>/MEMORY.md`. Есть —
  прочитай индекс. Если тема разговора в нём встречается — прочитай соответствующую
  заметку до ответа. Индекса нет — памяти по проекту пока нет, это норма.
- По команде «зафиксируй» и при явных решениях/договорённостях с пользователем —
  запиши заметку по шаблону из скилла agent-memory и добавь одну строку в индекс
  `MEMORY.md` того же проекта.
- Кросс-проектные выводы — в `~/.agents/memory/_general/`, автоматически не читается.
```

3. Создать для текущего проекта `~/.agents/memory/<проект>/` и положить туда
   `MEMORY.md` из шаблона `templates/MEMORY.md`.
4. Имя папки — имя корневой папки проекта. Если два проекта называются одинаково,
   добавь суффикс родителя: `<родитель>-<проект>`.

## Протокол записи («зафиксируй»)

Достойно заметки: решение и причина, отвергнутый вариант и почему, договорённость
о процессе, найденный подводный камень. Не достойно: разовые действия, статусы
«сделал/не сделал», то, что и так написано в коде и README.

Порядок:

1. Создай `~/.agents/memory/<проект>/<тема-kebab>.md` по шаблону `templates/note.md`.
2. Заполни: `description` одной фразой — что внутри и когда применять; тело —
   решение, **Why** (почему так, что отвергли), **How to apply** (как применять
   в следующих сессиях).
3. Добавь в `MEMORY.md` строку `- [Название](<тема>.md) — однострочник`.
4. Обновляй существующую заметку, а не плоди дубли: тема та же — правь её и дату
   `modified`.

## Перенос из памяти Claude Code («перенеси память из Клода»)

Если у пользователя уже память Claude Code, заметки можно перенести целиком —
формат совпадает:

1. Определи клодовскую папку проекта: `~/.claude/projects/<путь-с-тире>/memory/`
   (путь проекта, где каждый небуквенно-цифровой символ заменён на `-`; кириллица —
   по тире за букву, поэтому имя папки выглядит как длинная цепочка тире).
2. Прочитай её `MEMORY.md`. Для тем, которых нет в нашем индексе, прочитай заметку
   и реши, жива ли она ещё (дата `modified`, актуальность).
3. Живые перенеси: скопируй файл в `~/.agents/memory/<проект>/` и добавь строку
   в индекс. Устаревшее — перескажи своими словами в новой заметке.
4. Клодовские файлы не изменяй: это память другого агента, читаем, не пишем.

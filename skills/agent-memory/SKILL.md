# agent-memory — память агента между окнами

Модель между окнами ничего не помнит — помнят файлы. Скилл повторяет встроенную память Claude Code
для программ, у которых её нет: Kimi Code, OpenCode, Codex. Claude Code он не нужен — у него своя.

Два места, у каждого своя работа:

| Где | Что помнит | Как меняется |
|---|---|---|
| `~/.agents/memory/<проект>/` на компьютере | человека и проект: кто он, его поправки, решения и почему, где что лежит | копится |
| `PROGRESS.md` в корне проекта | где остановились и что дальше | переписывается |

Где остановились — только в `PROGRESS.md`. В памяти этого нет: два места разойдутся, и новое окно
не поймёт, какому верить. Файл в проекте ещё и виден человеку, переживает переименование папки, а
OpenCode умеет класть его в окно сам.

## Устройство

```
~/.agents/
├── AGENTS.md                 главный файл: программа кладёт его в каждое окно
├── memory/
│   └── <имя проекта>/        память одного проекта
│       ├── MEMORY.md         оглавление: строка «Проект: <путь>» и строка на заметку
│       └── <тема>.md         заметки
└── skills/agent-memory/      этот скилл

<проект>/
└── PROGRESS.md               где остановились
```

**Проект** — корень git-репозитория папки окна; без git — сама папка окна.

**Как найти память проекта.** Папка памяти названа именем проекта, чтобы человек узнавал её
глазами. Но имена повторяются (у многих есть `bot` и `test`), поэтому настоящий признак — строка
`Проект: <полный путь>` в `MEMORY.md`. Ищи по ней:

```bash
p=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
grep -lxF "Проект: $p" ~/.agents/memory/*/MEMORY.md
```

```powershell
$p = git rev-parse --show-toplevel 2>$null; if (-not $p) { $p = (Get-Location).Path }
Select-String -Path "$HOME\.agents\memory\*\MEMORY.md" -Encoding utf8 -SimpleMatch "Проект: $p" | Select-Object -ExpandProperty Path
```

Почему не ключ из пути, как у Claude Code: его заменяет каждый знак, кроме латиницы и цифр, на
`-`, и в терминале с другим языком русская буква даёт то одно тире, то два. Две программы
насчитали бы одному проекту разные папки, и память молча разделилась бы.

**Не нашлось.** Памяти у проекта пока нет — это норма. Заводишь её при первой записи:

1. Папка `~/.agents/memory/<имя папки проекта>/`. Такое имя уже занято другим проектом — добавь
   `-2`, `-3`.
2. В ней `MEMORY.md` по [шаблону](templates/MEMORY.md), со строкой `Проект: <путь>` ровно в том
   виде, как его выдала команда выше.

**Проект переехал.** По пути не нашлось, а папка с тем же именем есть, и в ней другой путь —
спроси человека: «Это тот же проект, что был в <старый путь>?» Да — поправь строку `Проект:`.

## Заметки

Четыре типа, как у Claude Code:

| Тип | Что | Пример |
|---|---|---|
| `user` | кто человек: роль, опыт, как с ним говорить | «Пишет на Python, в JavaScript новичок — объясняй фронт через знакомое» |
| `feedback` | его поправка или одобренный подход — с причиной | «Не добавлять зависимости без вопроса: был случай, сломалась установка» |
| `project` | цели, решения и ограничения, которых не видно в коде | «Бот только для одного салона: мультиаккаунт не делаем, решили 2026-11-10» |
| `reference` | где что лежит: ссылки, папки, доски, документы | «Макеты — в Figma, ссылка такая-то» |

**Когда писать.** Сам, не дожидаясь просьбы, как только узнал то, что пригодится в следующих окнах.
И по словам человека: «запомни», «зафиксируй». Поправка человека — почти всегда заметка
`feedback`: иначе в следующем окне ошибка повторится.

**Что не писать:**
- где остановились — это `PROGRESS.md`;
- этапы текущей работы — у них свой файл (в ките — `tasks.md` изменения);
- то, что видно в коде, README или истории git;
- разовые действия: «запустил тесты», «поправил опечатку»;
- пароли, ключи, личные данные других людей.

**Как писать:**
1. Посмотри в оглавлении, нет ли заметки на ту же тему. Есть — правь её, а не заводи вторую.
2. Новая — `<тема-через-дефис>.md` по [шаблону](templates/note.md). Даты — числом
   (`2026-11-18`), а не «вчера».
3. Строка в `MEMORY.md`: `- [Название](файл.md) — что внутри и когда пригодится`. Одна строка,
   до 150 знаков. Оглавление держи до 200 строк: в окно идёт только оно.
4. Заметка оказалась неверной — исправь или удали вместе со строкой в оглавлении.

## Просьбы человека

- **«Что ты помнишь?»** — перескажи оглавление своими словами, без путей и разметки.
- **«Забудь …»** — удали заметку и строку в оглавлении, скажи, что удалил.
- **«Запиши, где остановились»** — перепиши `PROGRESS.md` по [шаблону](templates/progress.md):
  что сделано, на чём стоп, что дальше. Старое убери.

## Память Claude Code

Claude Code хранит память проекта в `~/.claude/projects/<путь проекта, где каждый знак, кроме
латиницы и цифр, — тире>/memory/`. Найти: `ls ~/.claude/projects | grep -- "<имя папки проекта>"`
и выбрать папку, которая совпадает с полным путём.

- **«Посмотри, что помнит Claude Code»** — прочитай его `MEMORY.md` и нужные заметки, перескажи.
- **«Перенеси память из Claude Code»** — по каждой заметке, которой нет у нас, реши, жива ли она
  (дата, не устарели ли пути и имена), живые скопируй к нам со строкой в оглавлении. Формат тот же.
- Файлы Claude Code не меняй никогда. Обратно — только по прямой просьбе и только копированием.

## Установка («поставь память»)

Один раз на компьютер. Спроси, в каких программах человек работает, и подключи каждую.

**0. Сам скилл** должен лежать в `~/.agents/skills/agent-memory`: на этот путь ссылается главный
файл. Нет его там — склонируй хаб `https://github.com/wolkart/aifuture_hub.git` в `~/aifuture_hub`
и поставь ярлык `~/.agents/skills/agent-memory` → `~/aifuture_hub/skills/agent-memory` (на Windows —
`mklink /J`). Обновить скилл потом — `git pull` в `~/aifuture_hub`.

**1. Главный файл.** `~/.agents/AGENTS.md`: нет — создай; есть — проверь, есть ли раздел
`## Память`. Нет раздела — допиши, есть старый — замени. Текст раздела — в
[templates/agents-block.md](templates/agents-block.md). На Windows замени в нём команду поиска на
вариант для PowerShell из «Устройства».

**2. Папка памяти.** Создай `~/.agents/memory/`.

**3. Программы.** Каждая должна класть главный файл в окно сама:

| Программа | Что сделать | Как проверить |
|---|---|---|
| Kimi Code | ничего: читает `~/.agents/AGENTS.md` сама | новое окно, вопрос «какие у тебя правила про память?» |
| Codex | ярлык `~/.codex/AGENTS.md` → `~/.agents/AGENTS.md` | `codex debug prompt-input < /dev/null \| grep "## Память"` |
| OpenCode | ярлык `~/.config/opencode/AGENTS.md` → `~/.agents/AGENTS.md`; в `~/.config/opencode/opencode.json` — `"instructions": ["PROGRESS.md"]` | `opencode debug config` показывает `instructions`; новое окно, вопрос про память |
| Claude Code | память не ставь — у него своя | — |

Как ставить ярлык (macOS, Linux):

```bash
ln -s ~/.agents/AGENTS.md ~/.codex/AGENTS.md
ln -s ~/.agents/AGENTS.md ~/.config/opencode/AGENTS.md
```

- **Файл программы уже есть и не пустой** — не затирай. Покажи человеку, что в нём, перенеси нужное
  в главный файл и только потом ставь ярлык. Это его настройки, они могут быть важны.
- **`opencode.json` уже есть** — допиши `"instructions"` к тому, что там есть; если массив уже
  есть — добавь в него `"PROGRESS.md"`. Остальное не трогай.
- **Строка `"instructions": ["PROGRESS.md"]`** — OpenCode ищет этот файл в каждом проекте, от папки
  окна вверх до корня, и кладёт в окно сам. Нет файла — молча пропускает.
- **Windows.** Ярлык на файл без режима разработчика не создаётся. OpenCode — вместо ярлыка
  `"instructions": ["~/.agents/AGENTS.md", "PROGRESS.md"]`. Codex — скопируй главный файл в
  `%USERPROFILE%\.codex\AGENTS.md` и допиши в главный файл строку: «Правишь этот файл — скопируй
  его в `~/.codex/AGENTS.md`».
- **Claude Code**, если человек хочет `PROGRESS.md` во всех проектах: в `~/.claude/CLAUDE.md`
  допиши только пункт про `PROGRESS.md` из блока. Пункты про память не нужны.

**4. Проверка.** Новое окно в любом проекте, вопрос: «Что ты обо мне помнишь и где мы
остановились?» Ответ «памяти по проекту пока нет» на первом проекте — правильный. Неправильный —
агент не знает ни про `~/.agents/memory`, ни про `PROGRESS.md`: главный файл до программы не
дошёл, проверь шаг 3.

## Где спотыкаются

- **Codex и Kimi Code не поднимаются выше корня git.** Окно открывай в папке проекта, а не в общей
  папке над проектами.
- **Модель может не открыть файл.** Главный файл в окно кладёт программа, а оглавление и
  `PROGRESS.md` модель открывает сама по правилу. Страховка — фраза человека «продолжаем» в начале
  окна и «запиши, где остановились» в конце шага.
- **Публичный репозиторий.** `PROGRESS.md` — рабочая заметка: проверь, что он в `.gitignore`, или
  спроси человека.

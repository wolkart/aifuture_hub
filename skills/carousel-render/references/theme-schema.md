# theme-schema.md — устройство темы

Тема — единственное место, где живут переменные внешнего вида. Хочешь другой
цвет, шрифт, вес, кегль, аватарку — правишь тут, код не трогаешь.

**Где лежит.** Вне репозитория, путь в `.env` через `THEME_PATH`. Рядом с
`theme.json` ожидаются папки `fonts/` и `assets/`. Так личный стиль не уезжает
в публичный репозиторий. Образец нейтральной темы — `themes/example.json`.

**Проверка:** `python3 scripts/theme.py <путь к theme.json>` — печатает список
проблем либо «тема годна».

## Блоки

### `формат`

```json
"формат": { "ширина": 1080, "высота": 1350, "масштаб_рендера": 2 }
```

`масштаб_рендера: 2` — снимать в двойном размере и ужимать. Текст заметно
чище, чем при съёмке 1:1.

### `фоны`

Радиальные градиенты в две точки. `тёмный` идёт на обложку и CTA, `светлый` —
на тело и тело-список.

```json
"фоны": {
  "тёмный":  { "тип": "radial", "стопы": ["#222147", "#020105"] },
  "светлый": { "тип": "radial", "стопы": ["#FFFFFF", "#E0E9FF"] }
}
```

### `цвета`

Все восемь обязательны.

| Ключ | Где виден |
|---|---|
| `заголовок_обложки` | Крупный текст обложки |
| `акцент` | Слова в `**…**` на обложке и CTA |
| `текст_тела` | Текст светлых карточек |
| `текст_на_тёмном` | Подзаголовок обложки, текст CTA |
| `должность` | Вторая строка подписи |
| `бейдж_на_тёмном` | «ЛИСТАЙ» на тёмной карточке |
| `бейдж_кружок_на_светлом` | Кружок бейджа на светлой |
| `бейдж_текст_на_светлом` | Стрелка внутри кружка |

### `шрифты`

```json
"шрифты": {
  "файлы": { "oswald": "fonts/Oswald.ttf", "montserrat": "fonts/Montserrat.ttf" },
  "роли": {
    "заголовок_обложки":    { "семейство": "Oswald", "вес": 700 },
    "подзаголовок_обложки": { "семейство": "Oswald", "вес": 700 },
    "текст_тела":           { "семейство": "Montserrat", "вес": 500 },
    "выделение_тела":       { "семейство": "Montserrat", "вес": 700 },
    "заголовок_списка":     { "семейство": "Montserrat", "вес": 800 },
    "подпись_имя":          { "семейство": "Montserrat", "вес": 600 },
    "подпись_должность":    { "семейство": "Montserrat", "вес": 400 },
    "бейдж":                { "семейство": "Montserrat", "вес": 300 }
  }
}
```

Файлы — **вариативные** TTF: один файл закрывает все веса, поэтому вес
задаётся числом, а не отдельным начертанием. Оба шрифта под OFL, кириллица
включена. Скачать: `python3 scripts/fonts.py "<папка темы>"`.

Шрифты встраиваются в карточку как `data:` URI. Ни одного внешнего запроса —
и заодно снята блокировка загрузки шрифтов с `file://`, из-за которой Chrome
молча свалился бы в засечный фолбэк.

### `ступени`

Кегль ходит по конечному числу ступеней, а не подгоняется плавно: плавная
подгонка даёт десятки разных размеров и убивает узнаваемость ленты. Ровно
**три ступени, по убыванию**.

```json
"ступени": {
  "обложка_заголовок": [200, 150, 110],
  "обложка_подзаголовок": [56, 48, 40],
  "тело": [60, 52, 44],
  "тело_список": [42, 37, 32],
  "cta": [50, 44, 38]
}
```

Скилл берёт крупную, мерит фактическое переполнение в браузере и спускается
ниже, только если не влезло. Не влезло на минимальной — сообщает, на сколько
символов резать, и не ужимает молча.

> Значения выше — рабочий старт, снятый с карточек автора при калибровке.
> Подгонять их — нормально; ломать правило «три по убыванию» — нет.

### `типографика` (необязательный)

Безразмерные тонкости, у каждой в CSS свой дефолт — блок можно не писать.

```json
"типографика": {
  "трекинг_обложки": "-0.05em",
  "интерлиньяж_обложки": "0.95",
  "декор_размер": "340px",
  "декор_верх": "90px",
  "декор_право": "60px",
  "декор_прозрачность": "0.55",
  "декор_цвет": "#D97757",
  "значок_размер": "215px",
  "значок_отступ": "52px",
  "значок_цвет": "#D97757",
  "значок_фильтр": "none"
}
```

Значения идут в CSS как есть, без приписывания `px` — поэтому сюда кладут `em`,
множители интерлиньяжа и прозрачность. Кегли, наоборот, живут в `ступени` и
всегда в пикселях.

### `ассеты`

```json
"ассеты": { "спарк": "assets/claude-code.svg" }
```

Значок для вида обложки `декор`. **SVG предпочтителен растру:** масштабируется
без мыла на любом кегле и перекрашивается из темы, поэтому второй файл под
тёмный и светлый фон не нужен.

Перекраска работает потому, что SVG **вставляется в разметку**, а не через
`<img>`. Через `<img src="data:...svg">` картинка остаётся отдельным документом,
`currentColor` в ней не наследует цвет страницы, и значок выходит чёрным. Чтобы
цвет приходил из темы, в самом файле должно быть `fill="currentColor"`.

Растровый значок тоже поддержан — просто без перекраски.

### `обвязка`

Единственное, что зависит от площадки: у IG хэндл одной строкой, у LinkedIn
имя с должностью в две, и аватарки разные.

```json
"обвязка": {
  "IG": {
    "аватар": "assets/avatar-ig.png",
    "подпись": ["@ai_rtem"],
    "позиции": {
      "обложка":     { "бейдж": "верх-центр", "подпись": "низ-лево" },
      "тело":        { "бейдж": "низ-право",  "подпись": "низ-лево" },
      "тело-список": { "бейдж": "низ-право",  "подпись": "низ-лево" },
      "CTA":         { "бейдж": "нет",        "подпись": "верх-центр" }
    }
  }
}
```

`подпись` — список: одна строка либо две (вторая набирается цветом
`должность`). Позиции бейджа: `верх-центр`, `низ-право`, `нет`. Позиции
подписи: `низ-центр`, `низ-лево`, `верх-центр`, `нет`.

Место обвязки резервируется полосами в паддинге карточки, поэтому текст не
может уехать под подпись. Полосы заданы в `layouts/base.css`
(`--полоса-верх` / `--полоса-низ`); лейаут `CTA` расширяет верхнюю, потому что
подпись там крупная.

**Полоса держится только там, где обвязка реально стоит.** Убрал бейдж вниз —
верх освободился, и содержимое получает эту высоту, а не резервирует её зря.
Это не косметика: списочный слайд из шести пунктов при бейдже внизу садится на
ступень крупнее, потому что ему достаётся 80 лишних пикселей.

Отсюда рабочий приём: **позиция обвязки — это ещё и регулятор места под текст.**
Плотному слайду разведи обвязку по углам (`низ-лево` + `низ-право`),
воздушному — оставь по центру.

## Вторая тема для проб

Инверсия «светлая обложка, тёмные буквы» и подобные эксперименты — **отдельный
файл** темы, основной не трогать. Переключение — полем `meta.тема` в
`slides.json`. Так стандарт остаётся стандартом, а пробы не портят
узнаваемость.

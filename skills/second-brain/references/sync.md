# Уровень 2 — синхронизация через GitHub

**Когда читать:** человек хочет мозг на нескольких устройствах или у агента на сервере. Уровень 1
уже стоит: папка, Git, фоновая задача.

**Что получится:** приватный репозиторий на GitHub. Фоновая задача, которая уже стоит, сама
начинает забирать оттуда правки и отправлять свои — как только у мозга появится `origin`. Ничего
нового на компьютере не ставится, кроме программы `gh`, если её нет.

`<скилл>` — `~/.agents/skills/second-brain`, `<мозг>` — путь к папке мозга.

## Шаги

**1. Программа gh.** `gh --version`. Нет — поставь с согласия: Мак — `brew install gh`, Windows —
`winget install --id GitHub.cli`. Нет и `brew` — https://cli.github.com.

**2. Вход в GitHub.** `gh auth status`. Не вошёл — `gh auth login --web --git-protocol https`:
человек жмёт кнопку в браузере. Потом `gh auth setup-git` — Git будет входить через `gh`.

**3. Ключи — до отправки.** Мозг уходит на чужой сервер, а из истории Git ключ не вычистить:

```bash
python3 -I <скилл>/scripts/migrate/scan_keys.py <мозг>
```

Каждое совпадение — глазами (большая часть — заглушки и куски ссылок). Настоящий ключ нашёлся —
остановись и скажи человеку: ключ надо перевыпустить, а историю мозга начать заново (`.git`
удалить, `git init`, первый коммит — шаг 4 уровня 1) — только с его согласия.

**4. Репозиторий.** Спроси имя (по умолчанию `second-brain`) и подтверждение: «Создаю приватный
репозиторий `<имя>` на GitHub и отправляю туда мозг — ок?» Потом:

```bash
cd <мозг>
gh repo create <имя> --private --source . --remote origin --push
gh repo view <имя> --json visibility -q .visibility
```

Последняя команда должна сказать `PRIVATE`. Иначе — сразу
`gh repo edit <имя> --visibility private --accept-visibility-change-consequences` и скажи человеку.

**5. Проверка.** Запусти задачу руками, не дожидаясь расписания:
Мак — `bash ~/.local/bin/second-brain-sync.sh <мозг>`, Windows — по
[windows.md](windows.md). Последняя строка — `ок`. На GitHub в репозитории свежий коммит.

**6. README мозга.** Допиши в раздел «Как это работает каждый день», после абзаца про Git:

```markdown
- **GitHub** — сайт, где хранится копия базы со всей историей. Репозиторий приватный: его вижу только я.

**Если компьютер спит.** Пока он спит, ничего не отправляется. Проснётся — всё уйдёт в течение 5 минут.

### Как убедиться, что всё работает

- Открыть репозиторий на GitHub: под списком файлов видно время последнего изменения — несколько минут назад.
- Или лог: на Маке `~/Library/Logs/second-brain-sync.log`, на Windows `%LOCALAPPDATA%\second-brain\sync.log`. Последние строки — «ок».
```

И в «Если что-то пошло не так», первым пунктом:

```markdown
**Всплыло уведомление «Второй мозг: нужна ручная правка».** Значит, одно и то же место в заметке успели поменять на двух устройствах между двумя сохранениями. Ничего не потеряно и ничего не перезаписано — программа просто остановилась и ждёт. Скажи агенту: «разбери конфликт во втором мозге».
```

## Второй компьютер

На другом компьютере тот же человек говорит «подключи второй мозг на втором компьютере» —
`SKILL.md`, «Второй компьютер»: клон этого репозитория, правило для агентов, фоновая задача.

## Где спотыкаются

- **Публичный репозиторий по ошибке** — проверка в шаге 4 обязательна.
- **Нет интернета** — задача пишет в лог «нет связи с GitHub» и повторит через 5 минут. Это не
  конфликт, разбирать нечего.
- **Конфликт** — уведомление приходит один раз, задача дальше сохраняет только на компьютере,
  пока человек не скажет «разбери конфликт».
- **Две синхронизации одновременно** (расписание и ручной запуск) — вторая видит замок и
  пропускает ход; ложного конфликта нет.

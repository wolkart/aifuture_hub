# Уровень 3 — второй мозг у агента на сервере

**Когда читать:** на сервере уже работает агент (Гермес, OpenClaw), и человек хочет, чтобы тот
видел и пополнял мозг — например, с телефона через Telegram. Нужен уровень 2: мозг уже на GitHub.

**Как устроено:** компьютер ⇄ GitHub ⇄ сервер. Обе стороны раз в 5 минут сохраняют изменения,
забирают чужие и отправляют свои. Агент на сервере видит мозг как обычную папку.

Команды с пометкой «на сервере» выполняются там (`ssh <сервер>`). Агент на компьютере может
выполнять их через `ssh` сам — с согласия человека. `<репо>` — `владелец/имя` репозитория мозга.

## Шаги

**1. Где агент ждёт заметки.** Узнай папку, через которую агент на сервере видит файлы: она в
настройках агента. Агент в Docker видит её под своим путём внутри контейнера — тебе нужен путь
снаружи, на самом сервере. Дальше `<папка>` — он. Узнай, от чьего имени агент пишет файлы
(на сервере): `stat -c '%u:%g' <папка>` — это `<uid:gid>` для шага 5.

**2. Ключ развёртывания** — ключ к одному этому репозиторию, а не ко всему аккаунту GitHub.
На сервере:

```bash
ssh-keygen -t ed25519 -N "" -C second-brain-server -f ~/.ssh/second_brain_deploy
cat ~/.ssh/second_brain_deploy.pub
```

Открытую часть (одна строка) — в файл на компьютере, и там:

```bash
gh repo deploy-key add <файл> -R <репо> --allow-write -t "сервер"
```

**3. Клон через порт 443** в **новую** папку рядом со старой. С серверов исходящий порт 22 часто
закрыт, поэтому Git ходит через `ssh.github.com:443`. На сервере:

```bash
ssh-keyscan -p 443 ssh.github.com >> ~/.ssh/known_hosts
git clone -c core.sshCommand="ssh -i ~/.ssh/second_brain_deploy -o IdentitiesOnly=yes -o ConnectTimeout=20" \
  ssh://git@ssh.github.com:443/<репо>.git <папка>.new
git -C <папка>.new config core.quotepath false
git -C <папка>.new config user.name "<имя агента>"
git -C <папка>.new config user.email "<имя агента>@server"
```

Имя в Git — чтобы в истории было видно, какие правки сделал агент.

**4. Переключить агента — только после клона.** Старую папку не трогай, пока клон не скачан:
иначе агент останется без заметок. В старой папке есть заметки, которых нет в мозге
(`diff -rq <папка> <папка>.new`, без `.git`), — сначала перенеси их в мозг. Потом: останови
агента → `mv <папка> <папка>.old` → `mv <папка>.new <папка>` → `chown -R <uid:gid> <папка>` →
запусти агента. `<папка>.old` удалить через неделю, спросив человека.

**5. Скрипт и расписание.** С компьютера:

```bash
scp ~/.agents/skills/second-brain/scripts/sync.sh <сервер>:/root/second-brain-sync.sh
```

На сервере:

```bash
chmod +x /root/second-brain-sync.sh
/root/second-brain-sync.sh <папка> --chown <uid:gid>        # руками один раз: последняя строка «ок»
( crontab -l 2>/dev/null; echo '*/5 * * * * /root/second-brain-sync.sh <папка> --chown <uid:gid> >> /var/log/second-brain-sync.log 2>&1' ) | crontab -
```

`--chown` возвращает файлы пользователю агента после каждой синхронизации: Git работает от
`root`, а агент в контейнере — от своего имени, и без этого не смог бы править заметки. Что папка
принадлежит другому пользователю, Git обычно не любит («dubious ownership»); скрипт сам говорит
ему, что эта папка своя (`safe.directory`). Ручные команды `git` на сервере в этой папке — с
`-c safe.directory=<папка>`.

**6. Исключение в инструкции агента.** Агент может по своей политике считать чужой
Git-репозиторий «только для чтения». В его инструкции (файл правил или личности агента) допиши:

> Папка `<путь, как её видит агент>` — второй мозг владельца. Заметки в ней писать можно, по
> правилам её `AGENTS.md`. Git в ней не трогай: изменения сохраняет фоновая задача.

**7. Проверка.** Попроси агента с телефона: «запиши во второй мозг: проверка связи». Через 5–10
минут заметка на компьютере: `git -C <мозг> log -3 --format='%an · %s'`. И обратно: заметка,
записанная на компьютере, через 5–10 минут видна агенту.

## Где спотыкаются

- **Порт 22 закрыт** — адрес через `ssh.github.com:443`, шаг 3.
- **Агент без заметок** — переключали раньше, чем скачался клон. Шаг 4 по порядку.
- **Агент не может писать** — файлы принадлежат `root`: забыли `--chown`.
- **Агент отказывается писать в репозиторий** — нет исключения из шага 6.
- **Конфликт на сервере** — уведомлений там нет: строка «КОНФЛИКТ» в
  `/var/log/second-brain-sync.log`, сервер перестаёт отправлять. Разбирать так же, как на
  компьютере (`SKILL.md`, «Разбери конфликт»), командами на сервере.

# Правила второго мозга

> Читай этот файл до любой работы в этой папке. Это единственный источник правил: `AGENTS.md` —
> ярлык на него (на Windows — указатель), `.claude/CLAUDE.md` его подключает.

## 1. Что это за база

Второй мозг человека — как его голова: какие есть проекты, что это, где лежат, что главное по ним
решено; знания, контент, сырьё, дневник. Читают агенты (Claude Code, Codex, OpenCode, Kimi, агент
на сервере, если он есть) и сам человек в Obsidian.

**Второй мозг — не память проекта.** Чтобы продолжить работу «с места, где остановились», есть
память проекта: `PROGRESS.md` в папке проекта и память агента. Сюда ход работы не дублируется.

**Быстрое и медленное:**
- **Медленное пишется сюда:** что за проект и где он лежит; решение с «почему», которое меняет
  направление; вышедший результат (опубликовал, запустил, продал) со ссылкой; кто есть кто.
- **Быстрое не копируется:** статус текущей работы живёт в проекте (`PROGRESS.md`, Git, свои
  списки задач). В карточке проекта — только ссылка, где его смотреть. Спросили «что по
  проектам» — прочитай эти файлы, а не пересказывай карточку.

**Три вида фактов.** Каждый факт — один из них:
- вечный — не стареет: «фронтенд-разработчик», «переехал в 2022»;
- с датой — правда на день записи: «на 2026-07: 30 тыс. подписчиков»;
- ссылка — где смотреть текущее значение: «подписчики — в статистике Instagram».

Меняющаяся цифра без даты («у меня 30 тыс. подписчиков», «8 лет опыта») не пишется: через месяц
это ложь, которая выглядит правдой.

## 2. Сначала проверь живое состояние

Прежде чем утверждать, чинить или писать про проект, прочитай настоящий файл, код, `PROGRESS.md`.
Не по памяти и не по старой заметке.

## 3. Куда класть — порядок вопросов, решает первый «да»

1. **Про человека лично?** Дневник, работа над собой, личные разборы → `journal/`.
2. **Нужно, чтобы сделать конкретный проект?** → `projects/<проект>/`. Проверка: закроется
   проект — нужна ли заметка сама по себе? Нет — значит проектная, даже если похожа на знание.
3. **Публичный текст или материал для него?** Пост, сценарий, статья, рассылка → `content/`.
4. **Чужой материал как есть?** Статья, транскрипт, курс, выгрузка → `raw/`.
5. **Знание, верное само по себе?** Как что устроено, сервис, промпт, шпаргалка → `wiki/`.
6. **Закончилось или больше не действует?** → `archive/` (не удалять).

Не уверен между двумя — спроси человека одной строкой, а не клади «куда-нибудь». Инбокса для
человека нет: то, что он бросил не глядя, лежит в `raw/входящее/`, и агент раскладывает это по
правилу выше, когда человек просит «разложи входящее».

## 4. Карта папок

| Папка | Что внутри |
|---|---|
| `projects/` | Проекты. У каждого карточка `projects/<Проект>/<Проект>.md`: что это, где живут код и файлы, где смотреть статус, что главное решено. Рядом — материалы проекта |
| `content/` | Всё для публикаций: посты, сценарии, статьи и материалы для них |
| `wiki/` | Знания. Подпапки по темам заводятся по мере роста: `сервисы/`, `промпты/`, `шпаргалки/` |
| `raw/` | Сырьё как есть: статьи, транскрипты, курсы, выгрузки. `raw/входящее/` — то, что ещё не разложено |
| `journal/` | Дневник и личные разборы |
| `archive/` | Законченное |
| `templates/` | Шаблоны Obsidian: карточка проекта |
| `files/` | Картинки и вложения |

Проекты живут не здесь. Код и рабочие файлы проекта лежат в его папке на компьютере; здесь у
проекта только карточка-указатель и выводы. Репозитории сюда не переносятся.

## 5. Ключевые файлы

- `index.md` — каталог. Читай его первым: он дешевле поиска.
- `README.md` — объяснение базы для человека, простыми словами. Поменялось устройство базы —
  обнови README тем же языком.
- `About Me.md` (в Obsidian — «Обо мне») — факты о человеке: вечное, срезы с датой, что не
  утверждать. Не переименовывать: под этим именем его ищут скиллы.
- `projects/*/<Проект>.md` — карточки проектов.

**Каталог держи коротким.** Его читают в каждой сессии, поэтому в нём только то, что помогает
найти: проекты и знания — строкой на заметку; большие папки (выгрузки, курсы, архив) — одной
строкой на папку, например «`raw/курсы/Название/` — 120 заметок»; дневник — одной строкой без
содержимого. Новая заметка — строка в нужный раздел каталога.

Пересобрать каталог целиком и раздел «Заметки проекта» в карточках (на Windows — `python`
вместо `python3`):

```
python3 -I ~/.agents/skills/second-brain/scripts/index.py "<путь к мозгу>"
python3 -I ~/.agents/skills/second-brain/scripts/cards.py "<путь к мозгу>"
```

## 6. Что записывать без вопроса, а что — спросив

**Без вопроса:**
- новый проект → карточка по шаблону `templates/Карточка проекта.md` + строка в `index.md`;
- решение с «почему», которое меняет направление проекта → в карточку, раздел «Главное
  решено», с датой;
- вышедший результат → в карточку или в заметку контента: что, где лежит, ссылка.

**Спросить:**
- всё в `journal/`;
- переписать существующую заметку по новому источнику, перенести в `archive/`, удалить;
- правка `templates/`, `raw/`, `.obsidian/`.

## 7. Формат заметок

- Свойства в начале: `date` (ГГГГ-ММ-ДД), `type` (project, note, content, person…), `tags`,
  `description` — одна строка: что внутри (её показывает каталог). У проекта ещё `status`
  (active · on-hold · completed · archived) и `updated`.
- Ссылки `[[…]]` на всё упомянутое: проекты, людей, другие заметки.
- Названия — на языке человека. Датированные заметки — «Название (ГГГГ-ММ-ДД)».
- Ключи, пароли и токены не писать никуда.

## 8. Синхронизация

Папка — Git-репозиторий. Фоновая задача раз в 5 минут сама сохраняет изменения в историю; если
подключён GitHub — ещё забирает оттуда правки с других устройств и отправляет свои. Агентам
`git commit`, `push`, `reset`, `rebase` здесь не делать — только писать файлы. Исключения —
просьбы человека «разбери конфликт» и «верни как было» (скилл `second-brain`).

Облачные папки (iCloud, OneDrive, Яндекс.Диск, Dropbox) к этой папке не подключать: они ломают Git.

## 9. Не трогать

- `journal/` — только по прямой просьбе человека; в публичные тексты никогда не цитировать.
- `raw/` — сырьё неизменно; разложить `raw/входящее/` — можно.
- `archive/` — история: читать можно, переписывать нельзя.
- `templates/`, `.obsidian/`, раздел «Заметки проекта» в карточках (его пересобирает скрипт).

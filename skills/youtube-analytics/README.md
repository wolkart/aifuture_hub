# youtube-analytics — где применять

Скилл разведывает YouTube-каналы через официальный Data API v3: по `@handle`
собирает ролики с метриками, ранжирует «что залетело» и выгружает в
**структурированную базу** (Markdown-индекс + карточки + CSV + Obsidian Base).
Это разведка для **своего контента** (референс → переупаковка), а не копирование.

## Когда срабатывает

- «Разбери YouTube-канал», «что заходит на ютубе у X», «проанализируй мой канал»,
  «выгрузи ролики канала в таблицу», «какие тайтлы работают», «разбери вступление
  ролика», «собери референсы для ютуба».

Работает по **любому публичному каналу**, включая свой — механика одна и та же.

НЕ пишет тайтлы и описания (это `youtube-meta`), не ищет по ключевым словам,
не качает видео.

## Три режима

- **`scout`** (дефолт) — массово и дёшево: метрики + ранжирование + выгрузка базы.
  Канал на 300 роликов ≈ 14 юнитов из суточных 10 000.
- **`patterns`** — главный артефакт: семь срезов по уже собранным данным
  (медиана по месяцам, длина и состав тайтла, длительность, описание, топ/дно,
  ритм). Считается офлайн, квоту не тратит.
- **`thumbs`** — текст на превью: качает превью, снимает надписи Apple Vision
  (локально, бесплатно, 47 штук за 14 секунд) и считает срез признаков против
  кратности. Превью не хранятся — стираются после распознавания.
- **`enrich`** — выборочно по отмеченным роликам: вступление дословно с
  таймкодами, главы, топ-50 комментариев, разбор вступления по битам.

## Ранжирование: кратность к медиане своего типа

Shorts и длинные ролики лежат в одном списке загрузок, но метрики у них
несопоставимы. Поэтому медиана считается **отдельно** для каждого типа, а
ранжирование идёт по «во сколько раз ролик обогнал медиану своего типа».
Иначе шорт на 200k «побеждает» 20-минутный ролик, и выборка референсов ломается.

## Что нужно

- **`YOUTUBE_API_KEY`** — ключ из [Google Cloud Console](https://console.cloud.google.com/apis/credentials),
  в проекте должен быть включён именно **YouTube Data API v3**.
- **yt-dlp** — только для режима `enrich` (субтитры и главы, которых в API нет).
- **macOS + `swiftc`** — только для режима `thumbs` (Apple Vision распознаёт
  текст на превью на устройстве). Нет — режим отказывается, остальные работают.

```
cp .env.template .env
# YOUTUBE_API_KEY=<ключ из Google Cloud>
# YT_OUTPUT_DIR=<куда писать базу; дефолт ./youtube-analytics-output,
#                можно путь к Obsidian-волту>
```

## Выгрузка

**Папка на канал:** `<YT_OUTPUT_DIR>/<handle>/index.md` (две ранжированные
таблицы — длинные и Shorts, колонка «Тема» = кликабельная ссылка) +
`cards/<id>.md` + `export.csv` + `Разбор — тайтлы и паттерны.md`.
Плюс `<YT_OUTPUT_DIR>/_Разведка YouTube.base` — Obsidian Base со сводным
срезом по всем каналам.

Идемпотентно по id: повторный скаут не плодит дубли и **не затирает** ручные
заметки и секции, заполненные `enrich`.

## Чего скилл принципиально не может

**CTR превью, показы и кривую удержания публичный API не отдаёт ни по какому
каналу — включая твой.** Это OAuth-ветка (YouTube Analytics API) и только для
владельца канала. По чужому каналу удержание недостижимо в принципе, никаким
инструментом. Скилл говорит об этом прямо, а не подменяет ответ похожими
метриками.

## Хэндофф

- паттерны → `youtube-meta` (тайтл, описание, теги);
- вступления → `hook-base` (операция ПОЛОЖИТЬ, формат `youtube-intro`);
- Shorts → `reels-script`.

## Примеры вызова

```
разбери канал @nicksaraev — выгрузи ролики с метриками
```

```
patterns по последней разведке: какие тайтлы у него работают
```

```
enrich: разбери вступления топ-3 роликов
```

В ответ — сводка выгрузки, расход квоты и пути к файлам базы.

# YouTube Data API v3 — ручки, квота, подводные камни

Базовый URL: `https://www.googleapis.com/youtube/v3`. Ключ идёт параметром `key`.
Скрипты собирают запросы сами — этот файл нужен, когда надо дёрнуть ручку руками
или понять, почему что-то не пришло.

## Квота: 10 000 юнитов в сутки

Сбрасывается в полночь по тихоокеанскому времени. Стоимость по ручкам:

| Ручка | Юнитов | Что отдаёт |
|---|---|---|
| `channels.list` | 1 | Канал: название, подписчики, id плейлиста загрузок |
| `playlistItems.list` | 1 за страницу (50 шт.) | id роликов из плейлиста загрузок |
| `videos.list` | 1 за пачку (50 id) | Метрики, тайтл, описание, длительность, теги |
| `commentThreads.list` | 1 за страницу (до 100) | Комментарии верхнего уровня |
| **`search.list`** | **100** | **Не используем — см. ниже** |

**Канал на 300 роликов ≈ 14 юнитов:** 1 (`channels`) + 6 (`playlistItems`) +
6 (`videos`) + округление. То есть суточной квоты хватает на десятки каналов.

### Почему `search.list` не вызываем никогда

Две причины, и вторая важнее первой:

1. Он стоит 100 юнитов — 100 вызовов и квота на сутки кончилась.
2. **Он отдаёт неполную выборку.** Поиск по каналу не гарантирует все ролики
   и режет выдачу ~500 элементами. Плейлист загрузок отдаёт весь канал честно
   и стоит 1 юнит за 50 штук.

Если очень нужен поиск по ключевому слову — это отдельная задача с явным
согласием пользователя на расход квоты, а не часть скаута.

## Ручки по шагам

**Канал по хэндлу:**

```
GET /channels?part=snippet,statistics,contentDetails&forHandle=@nicksaraev&key=…
```

Берём отсюда `contentDetails.relatedPlaylists.uploads` — id плейлиста загрузок.
`statistics.subscriberCount` может отсутствовать: **подписчики ниже 1000 скрыты**,
и API просто не отдаёт поле. Пишем «скрыто», а не 0.

Если канал не находится по `forHandle` — пробуем `forUsername` (старые каналы)
или прямой `id=UC…`.

**Список роликов (пагинация по `nextPageToken`):**

```
GET /playlistItems?part=contentDetails&playlistId=UU…&maxResults=50&pageToken=…
```

Плейлист загрузок содержит и длинные ролики, и Shorts вперемешку — они
разделяются уже у нас по длительности.

**Метрики пачкой до 50 id:**

```
GET /videos?part=snippet,statistics,contentDetails&id=id1,id2,…&key=…
```

- `statistics.likeCount` отсутствует, если автор скрыл лайки → пишем пусто, не 0.
- `contentDetails.duration` — ISO 8601 (`PT15M53S`), парсится `metrics.parse_duration`.
- `snippet.thumbnails` — берём максимальное доступное: `maxres` → `standard` →
  `high` → `medium` → `default`.
- Приватные и удалённые ролики есть в плейлисте, но `videos.list` их не вернёт —
  поэтому число собранных роликов может быть меньше числа id.

**Комментарии (Tier-2):**

```
GET /commentThreads?part=snippet&videoId=…&order=relevance&maxResults=100&key=…
```

Текст лежит в `items[].snippet.topLevelComment.snippet.textOriginal`,
лайки — рядом в `likeCount`. Ответы на комментарии (`replies`) не тянем:
для разбора нужны верхнеуровневые реакции, а не ветки обсуждения.
Комментарии отключены у ролика → приходит `403 commentsDisabled`; это
не ошибка выполнения, просто пишем пусто.

## Про `snippet.tags` — проверено, вопрос закрыт

**Data API отдаёт теги чужих каналов.** Боевой прогон 2026-08-09 по
`@nicksaraev`: теги пришли у **299 роликов из 300** (единственный без тегов —
ролик, где автор их не проставил). Расхожее мнение «теги видны только
владельцу» не подтвердилось. Обходной путь через yt-dlp не нужен.

## Замеры боевого прогона (2026-08-09, `@nicksaraev`)

| Что | Факт |
|---|---|
| Роликов собрано | 300 (лимит выборки, канал больше) |
| Время | **5 секунд** |
| Расход квоты | **13 юнитов** из 10 000 (расчётные ~14 сошлись) |
| Скрытых лайков | 0 |
| Подписчики | пришли (492 000) |

То есть суточной квоты хватает примерно на **760 таких прогонов**. Экономить
на скауте смысла нет — узкое место не квота, а внимание при чтении срезов.

## Ошибки

| Что пришло | Что значит | Что делать |
|---|---|---|
| `403 quotaExceeded` | Квота на сутки кончилась | Сказать честно; сброс в полночь по тихоокеанскому времени. Не пытаться обойти |
| `403 commentsDisabled` | Автор отключил комментарии | Не ошибка: поле пусто, идём дальше |
| `400 keyInvalid` | Ключ неверный или API не включён | Проверить, что в проекте Google Cloud включён именно **YouTube Data API v3** |
| Пустой `items` в `channels` | Хэндл не найден | Попробовать `forUsername` или прямой `id=UC…` |

**Ключ никогда не печатается.** В сообщениях об ошибках URL проходит через
`yt_api.safe_url()`, который заменяет значение `key=` на `***`.

## Чего в публичном API нет вообще

Ни по какому каналу, включая свой, без OAuth:

- CTR превью и показы (impressions),
- средняя доля просмотра и кривая удержания,
- watch time, источники трафика, демография,
- субтитры (`captions.download` требует OAuth владельца — поэтому субтитры
  берём через yt-dlp).

Всё это живёт в **YouTube Analytics API** и только для своего канала после
OAuth-авторизации. Это отдельная ветка, в этом скилле её нет.
